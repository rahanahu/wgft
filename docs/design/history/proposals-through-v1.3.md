- IPv6 の扱い(VPS に v6 があるなら prerouting に `ip6` を足すだけで済む可能性が高いが、自宅側の宛先指定と絡む)
- IPv6 の送信元の Admission Policy。
  v1 は IPv4 でない送信元を拒む(7a.9 節)。
  対応するときは、同じ IR と両方のコンパイラに IPv6 の set を加える
- 1 つの `listen_port` に対する複数エージェントへの振り分け(フェイルオーバー用途。
  v1 では 1 ルール 1 エージェント)
- エージェント用 API の証明書ローテーション。
  全体状態に「次の証明書ハッシュ」を載せ、エージェントがピン留め経路で受け取ったものだけを状態ファイルに追記する方式を想定している。
  v1 では実装せず、秘密鍵が漏れた場合の対処は `teardown --purge` と全エージェントの再登録とする(5.1 節)
- 拒否リストを外部のブロックリストから自動更新するか
- 管理 UI の `public` 待ち受け(11 節)。
  必要になった場合の実装項目は 11 節に列挙してある
- エージェントのカーネルモードのループバックの宛先。
  v1.2 は拒む(7b.2 節)。
  要望が出たら、wgft0 に `route_localnet` を立て、DNAT を経ずにループバックを宛先とするパケットを input で捨てる方法を v1.3 で検討する。
  その守りの行はまだ試していない
- server にエージェントのモードを知らせるか。
  v1.2 は知らせない(7b.6 節)。
  `server doctor` と Web UI が「リスナー」と「DNAT」を書き分けられるようになるが、wire と管理用 API への加算が要る。
  v1.3 で、経路の図の `listener / target` の節点の分割と一緒に見直す
- 範囲の TCP のルールの接続確認の作り直し。
  v1.2 のカーネルモードは範囲ごとの先頭のポートだけを試し、ユーザー空間モードはポートごとに試す(7b.3 節)。
  両方のモードで、診断の副作用を範囲の幅に比例させない試し方を後の版で検討する
- エージェントのカーネルモードの Docker の配置。
  v1.2 は手順に書かない(7b.5 節)。
  要る権限とネットワークの設定は未確認である
- エージェントのカーネルモードで、ホスト自身の全アドレスに bind したソケットから応答する UDP のサービスの応答が client に戻らないこと(7b.2 節)。
  v1.2 は制限として文書に書き、直さない。
  wgft0 の経路に、優先する送信元としてホストの LAN のアドレスを与える直し方が考えられるが、未確認である。
  この経路はエージェント自身が wgft0 へ送るデータグラム(7b.1 節のセッションの回復)にも使われるので、その送信元への影響も未確認である
- ユーザー空間モードの中継が持つカーネルの TCP ソケットの送信のキューと、中継が閉じた後に送り残しか順序外の受信のデータを持って残るソケット(7 節)。
  どちらも上界を持たない保持として残し、v1.3.0 の後に設計し直す(2026-10-01、所有者の決定)。
  相手が読むのを止める操作を繰り返すと、ホスト全体の `tcp_mem` を使い、同じホストの無関係な TCP を遅くしうる。
  1 本の保持が長く続くことはラボで確かめたが、繰り返したときのホスト全体への影響は未確認である。
  直し方の候補には、枠を戻すときに組にしたカーネルのソケットの送信のキューを確かめる方法、LAN 側の送信のバッファも固定する方法、閉じる前に送り残しの量で閉じ方を変える方法があるが、どれも速さと保持への効き目を確かめていない。
  中継が閉じた後のソケットは、穴の後ろの順序外の受信のデータも持ったまま、FIN の再送が尽きるまで残りうる(7 節)。
  送り残しの量で閉じ方を変える方法はこの保持に効かないので、この保持も同じ設計で扱う
- ピアだけを変えるトランザクション。
  カーネルモードの `vpsd` は、エージェントの公開鍵の変更でも `table inet wgft` の全体を差し替え、全エージェントのルールの meter と `ct count` の状態を作り直す(6.1 節)。
  5.2 節の上限は差し替えの回数を抑えるだけである。
  `Plan` が変わらずピアの集合だけが変わるトランザクションでテーブルを差し替えない形を、後で設計する(2026-10-02、所有者の決定)。
  7a.3 節の `Observe` が比べる基準、ピアの追加と削除の順序、戻れない地点の後の修復との関係を含めて決める必要がある
