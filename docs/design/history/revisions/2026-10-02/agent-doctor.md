# 2026-10-02: agent-doctor

- 鍵の変更の頻度の上限による拒否を、server とエージェントの診断で見分けられるようにした(2026-10-02、5.2・7a.11・10.2a・10.2c 節、所有者の決定):上限で宣言を断ったことは、エージェントのログと `agent doctor` の制御の接続の理由の文言にしか現れなかった。
  `agent ls` の `STREAM` は `-` だけを示した。
  `server doctor` は、最終ハンドシェイクが新しい間、切断した他のエージェントと同じく、受け取り済みのルールが転送を続けているかもしれないと述べた。
  稼働中のエージェントの `agent doctor` も、受け取り済みのルールは stream が切れている間も転送を続けると案内した。
  断られた鍵はエージェントが今使っている鍵で、server のピアに入っていないので、この案内はどちらも当たらない。
  `vpsd` の拒否の行は `vpsd` の全体で 1 分に 1 行までだったので、あるエージェントの行が別のエージェントの行を隠しえた。
  所有者の決定に従い、上限と符号 1008 とバックオフは変えず、表示だけを直した。
  `vpsd` は上限で断った直近の時刻をエージェントの stream の状態とともにメモリの上に持ち、そのエージェントの公開鍵の宣言を受け付けると消す。
  記録は、その時刻に断ったことと、その後に宣言を受け付けていないことを述べ、今も断り続けていることは述べない。
  管理用 API のエージェント一覧に `key_change_refused_at` を加え、`agent ls` は切断しているエージェントの `STREAM` に拒否とその経過を示す。
  `server doctor` の `agent.connection` と、`agent doctor` の `stream.connection` に理由の符号 `key_change_limited` を加え、受け取り済みのルールの転送が続くという文言を出さない。
  `server doctor` がこの符号を使うのは、記録が試みを続けるエージェントのものと読める間だけである。
  独立レビューの指摘を受けて、1 回分の戻る間隔と再接続の待ちの上限の和より古い記録では、切断の既定の判定と案内に戻し、断った時刻を過去の事実として添えるだけにした。
  状態の分け方は変えないので、どちらのコマンドも最上位の判定と終了コードは変わらない。
  エージェントは close の符号と理由の文言から拒否を判定して制御ソケットの応答に載せ、その値を送らない旧い版のエージェントには `agent doctor` が記録された理由の文言で判定する。
  拒否のログの行はエージェントごとに 1 分に 1 行までにした。
  単体試験で次を確かめた。
  断った時刻を記録し、確立した接続は置き換えない。
  接続が切れても記録は残り、上限以外の失敗では変わらない。
  宣言を受け付けると、その後の全体状態の判定で接続を断った場合も記録は消え、接続を受け付けても消える。
  一度も断っていないエージェントは記録を持たない。
  拒否の行はエージェントごとに間引く。
  管理用 API は断ったエージェントにだけ時刻を返し、1 回分が戻って鍵が通ると返さない。
  `server doctor` は、最終ハンドシェイクが新しければ UNKNOWN、新しくなければ FAILED の `key_change_limited` を返し、接続しているエージェントでは記録を使わない。
  記録が 1 回分の戻る間隔と再接続の待ちの上限の和より古ければ、`agent_disconnected` の判定と案内に、断った時刻を述べる 1 文だけを添える。
  取り消した登録の記録は、同じ名前の次の登録の一覧に現れない。
  エージェントは実際の close の符号と理由の文言から拒否を判定し、`agent doctor` は判定の値と理由の文言のどちらからも `key_change_limited` を示す。
  ラボで、カーネルモードの `vpsd` とユーザー空間モードのエージェント 1 台を動かし、稼働中の `rotate-key` を続けて実行して上限を超えさせ、修正の前と後の表示を比べた。
  修正の前は、`agent ls` の `STREAM` が `-` で、`server doctor` はエージェントを DEGRADED とし、受け取り済みのルールが転送を続けているかもしれないと述べたが、ルールの TCP の接続は通らなかった。
  修正の後は、`agent ls` が拒否とその経過を示し、`server doctor` と `agent doctor` が `key_change_limited` を示して、転送が続くという文言を出さなかった。
  最終ハンドシェイクが古くなった後は `server doctor` が FAILED の `key_change_limited` を示した。
  1 回分が戻って鍵が通った後は、同じ `vpsd` のプロセスのまま、拒否の表示が消えた。
  拒否の後にエージェントを止め、記録が 1 回分の戻る間隔と再接続の待ちの上限の和より古くなった後は、`server doctor` が `agent_disconnected` の判定と案内に戻り、断った時刻を述べる 1 文だけを添えた。
  `agent ls` は拒否とその経過を示し続けた。
