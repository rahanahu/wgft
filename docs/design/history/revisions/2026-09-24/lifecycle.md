# 2026-09-24: lifecycle

- エージェントの conntrack の収束を実装した(2026-09-24):`internal/dataplane/linuxkernel/conntrack` に、テーブルの公開の後に、wgft0 から入って DNAT されたフローを今の公開へ収束させる部品を加えた。
  エージェントへの組み込みはまだ無い。
  7b.4 節が決めていなかった照合の細部を次のとおり決めた。
  wgft のフローは、DNAT の印、元の向きの送信元と宛先、応答の向きの送信元で見分ける。
  前の公開は列で受け取り、収束に失敗していた間の公開のフローも見分ける。
  呼び出し側は列を状態ファイルに残す。
  フローを作った公開は、DNAT の宛先を実際に公開した公開から先に探す。
  宛先がホスト名のポートは、公開の記録に宛先のアドレスが無ければポートだけで照合する。
  公開できなかったポートも宣言に含める。
  宣言の変わらないフローでも、アドレスまで照合できたフローの DNAT の宛先が今の許可一覧の外にあれば消す。
  ポートだけで照合したフローは許可一覧では消さない。
  前の公開が無ければ何も消さない。
  wgft0 に見立てた veth のラボでは、宛先を変えたルール、削除したルール、無効にした UDP のルールの成立済みのフローが、テーブルの差し替えの後も続き、収束の後に止まった。
  変わらないルール、名前の解決の結果だけが変わったルール、wgft の表が無い間に他のテーブルが DNAT したフロー、エージェントのホスト自身の接続は、収束の後も続いた。
  他のテーブルが DNAT したフローには、wgft が後で宣言し、その後に削除したポートのフローも含めた。
  同じ公開での 2 回目の収束は何も消さなかった。
  収束の後、宛先を変えた TCP のフローの利用者には新しい宛先の RST が届き、削除したルールのフローの利用者には何も届かなかった。
  7b.4 節の切れ方の記述を、この結果に合わせて直した。
