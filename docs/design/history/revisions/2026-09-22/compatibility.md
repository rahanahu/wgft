# 2026-09-22: compatibility

- v1.0 の互換性の保証(7a.11 節)の範囲を Linux に限定した(2026-09-22、所有者の決定):保証が拘束するのは Linux の server と Linux の agent であり、Windows と macOS の agent は暫定とし v1.0 の保証には含めない。
  理由は、Windows と macOS の実機での確認を所有者の都合で当分行えないことにある。
  確認していない挙動を保証に含める実利より、外部仕様を固定する v1.0 のリリースそのものが実機の空くまで無期限に止まる損の方が大きいと判断した。
  バイナリは今までどおり全プラットフォームで配り、配布や支援を打ち切る決定ではない。
  保証の対象に含めないことは、確認していない挙動を保証しないという意味であり、暫定である間も既知の挙動をわざと壊すことはしない。
  実機での確認が取れた時点で保証に格上げし、そのとき確認した内容をここに追記する。
  実機での確認の状況は、プラットフォームごとにではなく変更ごとに異なるので、変更単位で書く。
  一般的な動作(登録、トンネルの確立、LAN サービスへの中継、server と agent の復帰)は、2026-09-19 に Windows 11(非管理者権限)の実機と macOS(Apple シリコン)の実機の両方から、実機の VPS に対して確認済みである。
  7 節のトンネルの作り直しの watchdog(受信の経路が死んだ場合と、300 秒を超えるスリープからの復帰の両方でトンネルを作り直す)は、2026-09-21 に macOS の実機で確認済みだが、Windows の実機ではまだ確認していない。
  一方、この watchdog より後に加えた、5.2 節の ping/pong による stream の生死の判定と再接続は、Windows でも macOS でも実機で確認していない。
  この判定は、control stream が生きているかどうかを決め、繋ぎ直しの契機になる現在の中核の仕組みであり、これが両方の OS で実機未確認であることが、Windows と macOS の agent を今回の保証に含めなかったおもな理由である。
  なお、上記の watchdog の macOS での確認は Apple シリコンの Mac 1 台に限られ、README のとおり配布していない darwin/amd64 を含む他の機種と OS 版では確かめていないが、これは補足であり、保証に含めなかったおもな理由ではない。
