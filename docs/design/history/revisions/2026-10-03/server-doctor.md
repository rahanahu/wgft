# 2026-10-03: server-doctor

- エージェントが `net.ipv4.ip_forward` を読めず書けもしなかった場合の理由と、`server doctor` の案内から、0 という断定と再起動の勧めを外した(2026-10-03、7b.1 節、10.2a 節):カーネルモードのエージェントは、起動時に値を読めず、1 を書くことにも失敗すると、ルールの理由を「is not 1 and cannot be set」と述べていた。
  値を読めていないので、1 でないとは言えない。
  理由は、値が分からないことと、読みの誤りと書きの誤りの両方を示し、転送しないとは断定しない文に改めた。
  0 を読んで書けなかった場合の理由は変えていない。
  値を読めなかった後の 30 秒ごとの読み直しで 0 を読めたときは、起動時に書けなかった事実を保つため、0 を読んで書けなかった場合と同じ理由に置き換える。
  `server doctor` の所見の行も、値が分からないと述べる理由のときは、転送しないと断定しない。
  `server doctor` の `agent_ip_forward_off` の案内は、値を 0 と断定し、エージェントの再起動を勧めていた。
  この符号は 0 の場合のほか、読めず書けもしなかった場合と、0 を読んで書けなかった場合にも付き、再起動は書けない原因を除かない。
  案内は、そのホストで値を読み、1 でなければ `sysctl -w` で 1 にすること、書けない場合は再起動では直らないので、読み取り専用の `/proc` やコンテナの制限などの原因を除くこと、後で 0 に戻るなら設定を探すことを述べる文に改めた。
  旧い版のエージェントの理由にも当てはまる。
  理由の分類は `net.ipv4.ip_forward` を含むかだけを見るので変わらない。
  `agent doctor` は制御ソケットから今の値を読み、読めなければ `ip_forward_unreadable` とするので、同じ断定を持たず、変えていない。
  単体試験で、値を読めず書けもしない場合の理由が「is not 1」を含まず両方の誤りを含むこと、その理由を `server doctor` が `agent_ip_forward_off` に分類すること、0 を読んで書けない場合の理由が従来のままであること、案内が値を 0 と断定せず再起動を勧めないことを確かめた。
  ラボで、カーネルモードのエージェントの network namespace に、`/proc/sys/net/ipv4` へ tmpfs を重ねて `ip_forward` をディレクトリにした mount namespace を作り、読みと書きの両方を失敗させた。
  修正の前の版は、ルールの理由に「is not 1 and cannot be set」と「does not forward」を示し、`server doctor` の案内は値を 0 と断定してエージェントの再起動を勧めた。
  この版は、ルールの理由に両方の誤りと値が分からないことを示し、`server doctor` は同じ `agent_ip_forward_off` に分類して、新しい案内を示した。
  未確認:0 を読んで書けない場合のラボでの出力。
  単体試験だけで確かめた
