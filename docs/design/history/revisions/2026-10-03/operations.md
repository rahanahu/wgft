# 2026-10-03: operations

- server の撤去の間の排他(2026-10-03、9・10.3・11b・7a.11 節、所有者の決定):`server teardown` はロックの状態を `Inspect` で読むだけで、ロックを取らなかった。
  読めなければ警告を出して撤去を続けた。
  判定の後に `vpsd` が起動すると、撤去が稼働中の `vpsd` の wg0 とテーブルを消すか、撤去の後に資源が残りえた。
  `vpsd` はデータベースを開いてからロックを取っていたので、撤去がデータベースを消した後に空のデータベースを作りえた。
  撤去はデータベースを書き込みの形で開いていたので、`--dry-run` でも古い版のスキーマを上げた。
  所有者の決定に従い、何かを変える撤去は、ロックファイルが無ければ作ってロックを取り、データベースを開く前から終わるまで持つようにした。
  `--purge` はロックファイルを最後に消してからロックを放す。
  ロックの状態を読めなければ何も消さずに止まる。
  撤去はデータベースを読み取り専用で開く。
  `--dry-run` と `--yes` の無い `--purge` は何も作らず何も書かず、同じ判定だけをする。
  `vpsd` はデータベースを開く前にロックを取る。
  撤去が作ったロックファイルは、置き場のディレクトリの持ち主とグループに付け替える。
  server とエージェントのロックの取得は、取ったファイルがパスの今のファイルかを照合し、違えば開き直す。
  所有者の検討の段階では、root の作ったロックファイルを systemd が直すかは未確認だった。
  ラボで、持ち主の正しい置き場に root の持ち物の 0600 のロックファイルを置くと、同梱の unit の `vpsd` が開けずに終了コード 1 の再起動を繰り返すことを確かめ、付け替えを加えた。
  当初の実装は、置き場のディレクトリそのものが無ければロックを取らずに進めていた。
  独立レビューが、同梱の unit でこの場合の撤去の途中に `vpsd` を起動させ、`vpsd` が systemd の作った置き場でロックを取り、撤去がその wg0、テーブル、データベース、ロックファイルを消して `vpsd` が消されたデータベースの上で動き続けることを再現した。
  所有者の決定(何かを変える撤去は常にロックを取る)に合わせ、置き場を 0700 で作ってからロックを取るように直した。
  単体試験で次を確かめた。
  撤去はロックを取ってからデータベースを開き、どのカーネルの操作とファイルの削除の時点でもロックを持ち、ロックファイルを最後に消し、誤りで終わる場合もロックを放す。
  ロックファイルが FIFO か symlink なら、どのモードでも何も消さずに止まる。
  別のプロセスがロックを持てば、どのモードでも何も出力せずに拒む。
  `--dry-run` は、1 つ前の版のスキーマのデータベースの中身、権限、更新時刻、版を変えず、ロックファイルも作らない。
  撤去が作ったロックファイルだけを付け替える。
  置き場が無ければ何かを変える撤去は 0700 で作ってロックを持ち、何も変えない撤去は作らない。
  ロックを取った直後にロックファイルが消されたか差し替えられた場合、取得は開き直してパスの今のファイルのロックを返す。
  その際は古い記述子を閉じてロックを放す。
  取ったファイルそのものへの symlink に差し替えられた場合も食い違いとして扱い、開き直しが symlink を拒む。
  置き場のパスが行き先の無い symlink なら、撤去は何も消さずに止まる。
  `vpsd` はロックを取れなければデータベースを作らない。
  ラボで、同梱の unit で動かした `vpsd` に対して次を確かめた。
  稼働中はどのモードの撤去も終了コード 1 で拒み、何も変えない。
  停止した後の撤去は、ロックファイルの有無と `--purge` の有無のどの組み合わせでも成功し、残したロックファイルは `vpsd` の利用者の 0600 の持ち物で、その後の `vpsd` は起動する。
  `--dry-run` は、1 つ前の版のスキーマのデータベースの版、中身、権限、更新時刻を変えず、ロックファイルを作らない。
  修正の前の `--dry-run` は同じデータベースの版を上げ、権限を締め直した。
  撤去がロックを持つ間に起動させた `vpsd` は、データベースにも wg0 にも触れずに終わり、撤去が終わった後の unit の再起動で起動した。
  途中で強制終了した撤去の後も、`vpsd` は起動した。
  ロックファイルが FIFO の場合、撤去は wg0 とテーブルを残して止まった。
  ロックを `flock(1)` で持った間に起動させた `vpsd` は、データベースも wg0 も作らずに終わった。
  置き場が無い状態で `--purge` の撤去を止めている間に起動させた `vpsd` は、systemd が撤去の作った置き場を移した後もロックを取れずに終わり、撤去の後の再起動で起動し、消されたファイルを開いていなかった。
  置き場が無い状態の `--purge` の無い撤去が残した root の持ち物の置き場とロックファイルは、次の起動で systemd が移して持ち主を付け替え、`vpsd` は起動した。
  `--dry-run` と `--yes` の無い `--purge` は、無い置き場を作らなかった。
  未確認:作ってから付け替えるまでの間に撤去が強制終了された場合(コードから判断した)、systemd 252 以外の版の振る舞い、`DynamicUser` の利用者の番号が起動の間で変わった場合、同梱の unit 以外の配置(コンテナ、手で書いた unit)での付け替えの結果、非 root で手で動かす `vpsd` が一度も作っていない置き場を root の撤去が作った場合、`--purge` がロックファイルを消す前に古いファイルを開いた `vpsd` の筋書き(照合は単体試験だけで確かめた)
