# 2026-09-26: kernel-agent

- v1.2.0 の候補の確認で分かったエージェントのカーネルモードの制限と、v1.1.x へ戻すときの注意を書いた(2026-09-26):試験用の実機とラボで v1.2.0 の候補を確かめた。
  エージェントの無効化は、通信中のセッションを切り、TCP と UDP のルールと PROXY protocol v2 を付けたルールの転送を止めた。
  無効の状態は server とエージェントの再起動をまたいで保たれ、`status`、`server doctor`、`agent doctor` に示された。
  個別に無効にしたルールは、エージェントの有効化の後も無効のまま残った。
  v1.1.3 の server は版 9 のデータベースを終了コード 3 で拒み、データベースを変えず、systemd の unit は起動を繰り返さなかった。
  更新の前に取った写しでは v1.1.3 が起動した。
  README にエージェントの無効化の節を加え、Status の節のスキーマの版を 9 に直した。
  確認で分かったことは次のとおりである。
  カーネルモードのエージェントのホスト自身の UDP のサービスが、全アドレスに bind した通常のソケットから応答すると、応答が client に戻らない。
  原因と回避を 7b.2 節に書き、直すことを 13 節に残した。
  カーネルモードのエージェントでは、DF の付いた大きな UDP の応答のうち最初のものが失われる。
  7b.1 節に書いた。
  ユーザー空間モードの server の再起動の後、転送はエージェントの次のハンドシェイクまで戻らない。
  v1.1.3 と同じであり、6.3 節に書いた。
  カーネルモードのエージェントを teardown せずに v1.1.3 へ戻すと、wgft0 と `table inet wgft_agent` がカーネルに残り、v1.1.3 は `agent.json` をカーネルモードの記録を除いて書き直す。
  その後でも v1.2 の `agent teardown` は wgft0 とテーブルを消した。
  teardown の後に戻した v1.1.3 は、ユーザー空間モードで TCP、UDP、PROXY protocol v2 を正常に転送した。
  setup.md に、v1.1.x へ戻す前に teardown する順を書いた。
  未確認:wgft0 の経路に優先する送信元を与える直し方、受けたパケットの宛先のアドレスから応答の送信元を選ぶサービスへの影響、ユーザー空間モードの server でこの応答が落ちる仕組み、teardown せずに v1.1.3 へ戻した状態で残った wgft0 とテーブルが転送に与える影響
