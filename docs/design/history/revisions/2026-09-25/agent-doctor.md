# 2026-09-25: agent-doctor

- `agent doctor` が既定のデータディレクトリだけを見て未登録と断定しないようにした(2026-09-25、所有者の決定):`--data-dir` を付けずに打った `agent doctor` は、既定のデータディレクトリに `agent.json` が無いと「このホストは登録したことが無い」と断定し、新しい招待の発行を案内していた。
  エージェントが `--data-dir` で別のディレクトリを使う配置では、案内に従うと同じ名前の登録が拒まれ、その先の `wgft agent revoke` は動いているエージェントを切る。
  10.2c 節のとおり、所見は見たディレクトリについてだけ述べ、既定のディレクトリに登録済みの `agent.json` が見つからなかった実行では、同じ `--data-dir` で打ち直す案内を新しい招待と起動の案内より先に置くようにした。
  `host.privileges` がデータディレクトリの権限の不足を示す場合と終了の 1 行も同じである。
  エージェントの登録の 409 の拒否の文面も、動いているエージェントがその名前を使っている場合は revoke せずにそのディレクトリを指すよう先に述べる形にした。
  あわせて、root が持つ 0700 の既定のデータディレクトリの中に `agent.json` が無いとき、`agent.credentials` が「ファイルはあるが読めない」と述べていた誤りを直した。
  `os.ReadFile` の権限の誤りは、ディレクトリを辿れない場合にも返る。
  `agent.json` を stat し直して、stat も拒まれればディレクトリが拒んでいるとして、新しい理由の符号 `data_dir_unreadable` の UNKNOWN とした。
  層は `credentials_unreadable` と同じ 2 である。
  理由の符号の追加は 7a.11 節の開いた集合への加算である。
  ラボで、`--data-dir` を付けて動かしたカーネルモードのエージェントの横で、同じ利用者が `--data-dir` を付けずに打った `agent doctor` を、既定のディレクトリが無い場合と root が持つ 0700 の空のディレクトリの場合で確かめた。
  この変更の前の版は、前者で未登録と断定して新しい招待を案内し、後者で「ファイルはあるが読めない」と述べた。
  この版は、どちらでも見たディレクトリを名指して同じ `--data-dir` での打ち直しを先に案内し、後者では `data_dir_unreadable` を示した

- `agent doctor` が、固定した証明書と合わない server への接続を FAILED として示すようにした(2026-09-25、所有者の決定):server を `server teardown --purge` で作り直した後、古い証明書を固定したままのエージェントで `agent doctor` を打つと、`control connection` は UNKNOWN で「再試行するので問題ではない」と案内し、終了コードは 0 だった。
  証明書の不一致は再試行では直らない。
  10.2c 節のとおり、`stream.connection` の例外として FAILED `server_cert_mismatch` とし、エージェントのログと同じく新しい招待で登録し直すことを案内するようにした。
  総合判定と終了コードは動かさない。
  終了コード 1 は転送を担えないことに答え、制御ストリームが切れている間も受け取り済みのルールの転送はトンネルが保つ限り続くためである。
  server を作り直した場合の転送の止まり方は、トンネルとリスナーの検査が答える。
  判定には、制御ソケットの `doctor` の応答の制御ストリームの観測に加えた `pin_mismatch` を使い、送らない旧い版のエージェントには理由の文言で判定する。
  server のログの `TLS handshake error ... bad certificate` の行には、証明書を固定したエージェントの拒否として読むことと、新しい招待が要ることを添えた。
  どのエージェントかは、相手が名乗る前にハンドシェイクが終わるので示せない。
  ラボで、`server teardown --purge` で作り直した server に古い証明書を固定したカーネルモードのエージェントが繋ぎに行く場面を再現した。
  この変更の前の版の `agent doctor` は UNKNOWN と「問題ではない」を示し、この版は FAILED `server_cert_mismatch` と新しい招待の案内を示した。
  server のログの行にも案内が添った。
  案内のとおり新しい招待で起動し直すと、エージェントは登録し直し、転送が戻った。
  この場面の `agent doctor` の終了コードは、変更の前後とも 0 だった。
  エージェントの `tunnel` は、最終ハンドシェイクが古くなっても OK のままである。
  `agent doctor` はハンドシェイクの古さを判定しないためである(10.2c 節の「2 つのコマンドの境目」)。
  server の側では転送は止まっている
