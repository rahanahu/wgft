# 2026-09-25: security

- 認証情報ファイルの保存の途中で強制終了したときに残る一時ファイルを、エージェントの起動時に消すようにした(2026-09-25、ラボでの観測を受けて):ラボで保存の途中のエージェントを `kill -9` で止めると、データディレクトリに `.wgft-credentials-*` の一時ファイルが残ることが分かった。
  中身は rename の前の `agent.json` の写しで、wg の秘密鍵と恒久トークンを含む。
  `Save` は失敗して戻るときだけ一時ファイルを消し、強制終了では消す処理が走らない。
  保存はルールの公開、状態の変化、`rotate-key` のたびに走るので、停電やコンテナの強制停止でも同じことが起きうる。
  `rotate-key` で鍵を替えても、古い鍵を含む一時ファイルは残る。
  9 節に、起動時に状態ファイルの flock を取った後、データディレクトリの直下にある名前の合う通常ファイルだけを消す規則を加えた。
  flock を取らずに保存する書き手(`wgft agent pubkey` と、ロックファイルの無い停止中の `rotate-key`)の保存と重なると、Unix ではその書き手の rename が失敗し、Windows では片付けの削除か書き手の rename のどちらかが失敗するが、どちらでも状態ファイルは壊れず、この向きの失敗は許容することも書いた。
  Windows の向きは、一時ファイルを共有を許さずに開く `createSecureTemp` のコードから推したものである。
  登録の直後の最初の保存の途中で強制終了すると、恒久トークンと使用済みの接続文字列の印が一時ファイルにしか無い場合がある。
  片付けはこの一時ファイルも消すので、一時ファイルから手で回復する道は無くなるが、エージェントはもともと一時ファイルから回復しないので、この場合も新しい接続文字列を発行して登録し直せば済む。
  採らなかった案がある。
  一時ファイルの名前を固定して毎回上書きする案は、flock を取らない書き手と重なると書きかけのファイルを rename しうるので、状態ファイルを壊しうる。
  保存のたびに残りを消す案は、残りが強制終了の後にしか生じず、強制終了の後には起動が来るので、起動時の片付けとの差が小さい。
  そのうえ flock を取らない書き手の保存を失敗させる機会が保存のたびに増える。
  Linux の `O_TMPFILE` で名前の無いファイルに書いてから名前を付ける案は、起動時の片付けに重ねられる守りだが、Linux の一部のファイルシステムでしか使えず、既に残っている一時ファイルも回収できないので、今回は採らない。
  片付けは今回は起動時だけに行う。
  ラボで保存の途中に `SIGKILL` を当てて一時ファイルを残し、次の起動がそれを消して件数だけをログに出すことを確かめた。
  未確認:Windows と macOS の実機での片付け、Windows で書き手と片付けが重なったときの向き

- `--admin-tailscale` の待ち受けを tailnet に閉じた(2026-09-25、11 節、セキュリティレビューの指摘と所有者の決定):この待ち受けは tailnet のアドレスに bind するだけで、インタフェースへの縛りも接続元の検査も無かった。
  所有者の決定により、まずラボで外から届くかを確かめた。
  Tailscale そのものはラボに無いので、vps の network namespace に tailscale0 という名前の veth を作って tailnet の帯のアドレスを付け、`tailscale` コマンドの無い状態でインタフェースからの検出に任せた。
  client の namespace から公開のインタフェース越しにそのアドレス宛ての経路を加えると、`Host` に tailnet の IP を付けても `localhost` を付けても、管理用 API が応答し、接続文字列の発行も通った。
  Tailscale のソースの `util/linuxfw` が加える `ts-input` の規則を nftables で写して加えると、帯の外の送信元は変わらず届き、帯の内側の送信元だけが落ちた。
  修正として、11 節の「tailnet の待ち受けの閉じ方」のとおり、待ち受けをアドレスを持つインタフェースに縛り、接続元を Tailscale の帯に限った。
  修正の後は、両方のモード(ユーザー空間モードは非特権の利用者)で、`ts-input` の写しの有無によらず、公開のインタフェースからの接続が、送信元が帯の外でも内側でも届かず、tailscale0 の側の端末と VPS 自身からは届くことを確かめた。
  偽の `tailscale status --json` を置いて、コマンドからの検出でも同じインタフェースに縛られること、どのインタフェースにも無いアドレスが返ると待ち受けを開かずに起動が終了コード 1 で終わることも確かめた。
  縛りを外した変異では、帯の外の送信元は接続元の検査で閉じたが、帯の内側の送信元は `ts-input` の写しが無ければ届いた。
  接続元の検査を外した変異では、縛りだけで公開のインタフェースからの接続が全部拒まれた。
  独立したレビューが、縛りはインタフェースの番号に付くため、tailscale0 を同じ名前とアドレスで作り直すと待ち受けが消えた番号に縛られたまま残り、`vpsd` が動いたまま tailnet の側からも VPS 自身からも届かなくなることを、ラボで見つけた。
  縛りの無い修正前の待ち受けは、作り直しの後も届いていた。
  11 節のとおり、縛りを名前から番号に改め、2 秒ごとの見張りで閉じて開き直すようにした。
  ラボの両方のモードで、作り直しの後、インタフェースが消えてから戻った後、別の tailnet のアドレスで作り直した後に、tailnet の側と VPS 自身から数秒のうちに届くようになること、その間も公開のインタフェースからは届かないこと、古い tailnet の IP を `Host` に付けた要求が拒まれることを確かめた。
  見張りを外した変異では、作り直しの後に届かないままだった。
  再レビューが、開き直しの検出がインタフェースに落ちると MagicDNS 名が `Host` の許可から消え、wgft を再起動するまで戻らないことをラボで見つけたので、アドレスが前と同じなら前の名前を保つようにした。
  あわせて、開き直しの試みが続けて失敗する間の間隔を伸ばした。
  ラボで、偽の `tailscale status --json` が名前を返す状態で起動し、その後にコマンドを失敗させてインタフェースを作り直しても、名前を `Host` に付けた要求が通ることを確かめた。
  受け付け済みの接続が開き直しの間も応答を続けることは、ラボでは確かめていない。
  未確認:Tailscale そのものを動かしたホストでの確かめ(`ts-input` の規則は写しで確かめた。
  tailscaled の再起動が実際にインタフェースを作り直すかも含む)、送信元を書き換えないサブネットルータを経た接続、IPv6 の帯(待ち受けは IPv4 のアドレスで開くので、単体テストだけで確かめた)

- エージェントが送る文字列から運用者の端末を守るようにした(2026-09-25、独立したセキュリティレビューの所見と所有者の決定):エージェントは信頼の境界の外にあり(11 節)、ハートビートのトンネルの状態と理由・解決したエンドポイント・ルールごとの状態と理由・ルール ID は、`vpsd` の `internal/vpsd/stream` の hub が大きさの上限だけで受け取って保存し、`wgft agent ls`・`rule ls`・`status`・`server doctor` の人向けの出力にそのまま出ていた。
  エージェント側でも、`agent doctor` と `rotate-key` が制御ソケットの応答を大きさの上限なしで読み、その内容を root の端末に出していた。
  端末の制御文字を混ぜると、運用者の端末の表示を隠したり偽ったりできる。
  11 節と 5.2 節に、この脅威と 2 段の守りを書いた。
  受け口では、`internal/vpsd/stream` の hub がハートビートを保存する前に、対象の文字列を、まず表示できない文字を置き換え、続けて長さの上限で切り詰める順で加工する。
  逆の順(切り詰めてから置き換える)では、上限まで残した文字がすべて表示できない文字だった場合、置き換えによって保存する長さが上限の数倍まで膨らみうるという指摘を受けて、この順に決めた(5.2 節)。
  エージェント側は、`internal/agent` の `rotate-key`(`internal/agent/control.go`。
  既存の `rotateKeyReplyLimit`)と `agent doctor`(`cmd/wgft/agentdoctorlive.go`。
  新設の `DoctorReplyMaxBytes`)の両方の制御ソケットの応答の読み取りに、それぞれの上限を掛けた。
  上限に当たった読み取りは、二つとも「上限を超えた」と述べる誤りを返し、相手が早く接続を閉じた場合の EOF と見分けられるようにした(`internal/agent` の `ReadControlReply`)。
  表示の側では、新設した `internal/textsafe` package の `SanitizeForTerminal`(1 つの文字列を無害化する)と `SanitizeStrings`(構造体を再帰的に歩いて文字列の項目をすべて無害化する。
  `agent doctor` が読む `agent.DoctorResponse` に使う)を、`agent ls`・`rule ls`・`status`・`server doctor` の人向けの出力の組み立て(`writeLine`・`writeInternal`・`writeNext`・`writeStatusLine`・`agentRuleNote`・`checkDetailOf`・`firstNotOKDetail` など)と、エージェント側の `agent doctor`・`rotate-key` の出力(`writeValueLine`、`rotateKeyRunning`)から呼ぶ。
  表示できない文字の基準は `unicode.IsGraphic` が偽の文字とした(所有者の決定)。
  Unicode の図形文字(文字・記号・数字・約物・記号一式)と空白(Zs。
  ASCII の空白だけでなく、日本語の文中の全角スペースや no-break space も含む)はそのまま通し、それ以外の制御と書式の文字、つまり C0・C1 の制御文字、DEL、双方向の書字方向を変える制御文字、ゼロ幅の文字の大半、行と段落の区切り、言語タグの文字を逃がす。
  この基準は Go の `strconv.Quote` 自身が使う `unicode.IsPrint` より狭い。
  `IsPrint` は ASCII の空白以外の Zs もすべて逃がすため、日本語の文中の全角スペースが変わって見える食い違いが再レビューで見つかり、`IsGraphic` に絞った(所有者の決定)。
  zero-width joiner(U+200D)は Unicode の Cf 区分なのでこの基準でも逃がされ、これを含む合成の絵文字(家族の絵文字など)は崩れうるが、これは許容する(所有者の決定)。
  `group`・`label`・`detail`・`next`・`internal` はどの診断コマンドでも人向けの文であり `--json` の保証の対象ではない(10.2a・10.2b・10.2c 節、7a.11 節)。
  無害化を `internal/vpsd/doctor` の判定そのものではなく `cmd/wgft` の表示側に置いたのは互換の制約からではなく、判定の package を `internal/textsafe` から独立に保つための選択である。
  稼働中の `agent doctor --json` は `classifyDoctorReply` の `SanitizeStrings` によって `detail`・`next` も無害化されるが、停止中の `agent doctor --json`(`agent.json` を直接読む経路)はこの経路を通らないため、`agentDoctorJSONOf` でも同じ関数を掛け、稼働中と停止中で守りの差が出ないようにした。
  `agent ls --json`・`rule ls --json` は受け口の切り詰めと置き換えの分だけ値が変わり(7a.11 節に追記)、`status --json`・`server doctor --json` の `detail` はこれを組み立てる値がすでに受け口で安全なので変えていない。
  JSON へのエスケープ(`encoding/json` の既定の書式)は DEL と C1 の制御文字を生のまま出すので、`--json` の端末での安全さは値そのものの無害化に支えられており、JSON 自身のエスケープには支えられないことを 11 節に明記した。
  `agent ls` の RULES 列の組み立ても、ルールごとに文字列を `+=` で継ぎ足しており、ルール数について二乗になっていたので、同じ変更で `strings.Builder` に直した。
  `internal/textsafe` は `internal/resource`・`internal/lograte`・`internal/startup` と同じ葉の package とし、7a.7 節の package 一覧と `internal/dataplane/deps_test.go` の `TestPureLayersStayPure` に加えた。
  ホストの単体テストで、C0・C1 の制御文字(有効な UTF-8 で符号化した文字を含む)・双方向制御文字・ゼロ幅文字・行と段落の区切り・言語タグの文字・不正な UTF-8・非常に長い文字列を含むハートビートと制御ソケットの応答を読み、保存される値と各コマンドの人向けの出力と `agent doctor --json` に制御文字が生で出ないこと、日本語や絵文字や普通の空白(全角スペースと no-break space を含む)を含む普通の文字列は変わらないこと、`--json` の出力が有効な JSON のままであることを確かめた。
  次の変異をそれぞれ入れ、対応するテストが落ちることを確かめた。
  受け口の切り詰めと置き換えを外す変異(トンネルとルールの状態・トンネルのエンドポイントを含む)、表示の無害化を外す変異(`agent ls` の Tunnel.State、`agentRuleNote`、`checkDetailOf`、`firstNotOKDetail`、`writeValueLine`、`writeNext`、`agentDoctorJSONOf` のそれぞれについて)、制御ソケットの応答の大きさの上限を外す変異、`isUnsafeRune` を C0・C1 の制御文字だけに戻す変異、`isUnsafeRune` の基準を `unicode.IsPrint` に戻す変異(全角スペースと no-break space の試験は落ち、制御文字の試験は落ちないことを確かめた)、受け口の切り詰めと置き換えの順を逆にする変異、`ClipText` の rune の境目を探す処理を外す変異。
  制御ソケットの読み取りの変異は、応答を送り終えないまま接続を保持する模擬の相手に対して、読み取りが接続の期限まで止まることをテストが検出する形で確かめた。
