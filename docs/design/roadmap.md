# 制限と未実装の提案

以下の提案には実装する版と期限を定めていません。
現在の実装で扱わないものと、動作をまだ確かめていないものを区別します。

## 未対応の機能

| 対象 | 現在の制限 | 提案と判断に要ること |
| --- | --- | --- |
| IPv6 | トンネルと Admission Policy は IPv4 を対象にします | IR と nftables/Go の両コンパイラに IPv6 の集合を追加する設計が必要です |
| 複数エージェントへの振り分け | 1 ルールは 1 エージェントに所属します | フェイルオーバーを含む選択と切り替えの規則は未設計です |
| エージェント API の証明書の稼働中のローテーション | ピン留めした証明書を stream 内で更新しません | 次の証明書ハッシュを配る案は未実装です。秘密鍵の漏えい時は `teardown --purge` と全エージェントの再登録で対処します |
| 拒否リストの外部更新 | 外部ブロックリストからの自動更新は実装していません | 自動更新するかの判断を残します |
| 管理 UI の public 待ち受け | 認証と TLS を備えた `public` の選択肢は未実装です。通常の TCP 待ち受けは `WGFT_ADMIN=0.0.0.0:8686` などの非ループバックでも開け、起動ログの警告だけで停止しません | `public` の選択肢に要る認証、TLS、試行の制限は[管理用 API の接続経路](security/admin-transport.md#11-セキュリティ)に定めます |
| kernel エージェントのループバック宛先 | ループバックへの転送を拒否します | `route_localnet` と input の守りの組み合わせは未確認です |
| server へのエージェントのモードの通知 | `proto.Heartbeat` はモードのフィールドを持ちません | 手元の制御ソケットは `runtime_state.mode` を返しますが、server へは伝えません。wire、管理用 API、capability と経路図の変更は未実装です |
| 診断の `--report` と遠隔の診断 | CLI の `--json` と Web UI の server の診断は実装済みです | [報告の許可一覧](proposals/diagnostic-report.md)と、遠隔の証拠を要求する通信は未実装です |

## 現在の制限と未確認事項

- 範囲の TCP の接続確認:kernel エージェントは範囲の先頭だけを試し、ユーザー空間モードはポートごとに試します。
  診断の副作用を範囲の幅に比例させない方法は未設計です。
- kernel エージェントの Docker の配置:必要な権限とネットワークの設定は未確認です。
- kernel エージェントのホスト自身の UDP 宛先:全アドレスで待ち受けるサービスの応答が client に戻らない制限があります。
  wgft0 の経路へ優先する送信元を設定する候補は、セッションの回復への影響も未確認です。
- 中継のカーネル TCP ソケットの保持:Linux のユーザー空間モードでは、自然に終わった組を末尾の配送が終わるまで K に数えます。
  1 本の送信量に上界が無いことと、意図して切った組、カーネルモードの Relay、Windows と macOS の LAN 側の孤児は残ります。
  保持と未確認の範囲は[中継後の配送](userspace/tcp-retention.md#中継が終わった後の末尾の配送)に定めます。
- カーネルモードの server とユーザー空間モードの agent:conntrack の項目が期限で消えた後、送信元ごとの上限が配送中の接続を数えなくなる制限があります。
  [エージェントのメモリの前提](userspace/memory-agent-host.md)に定めます。
- ピアだけの更新:kernel の server は、公開鍵の変更でも wgft テーブルを差し替え、meter と ct count の状態を作り直します。
  Plan が同じ場合に差し替えを省くトランザクションは未設計で、Observe の比較、ピアの操作順、修復の規則を決める必要があります。
