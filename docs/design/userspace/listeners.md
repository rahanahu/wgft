# リスナーの収束とフローの帰属

リスナーはプロトコルとポートで同一性を判定します。
宛先が変わらない分割と統合では既存セッションを残し、予算の帰属を規則に従って移します。



収束の判定はポート単位で行います。
エージェントは全体状態から、各リスナーの宣言値 `(proto, port) → (実効宛先, 所属ルール ID)` を計算し、現在の状態と突き合わせる。
実効宛先は、ルールの `target` のポートに、そのポートの範囲内での位置を足したものです。
実効宛先の比較は文字列で行い、`target` がホスト名のときの名前解決はセッション確立時に行います。
DNS の変更でリスナーは閉じ直されず、新規セッションだけが新しい IP へ向く。

<a id="ポートが宣言に現れて現在にない"></a>
- ポートが宣言に現れて現在にない:開きます
<a id="ポートが現在にあって宣言にない"></a>
- ポートが現在にあって宣言にない:閉じます。
  そのポートの UDP セッション表を破棄し、中継中の TCP 接続もすべて切る。
  netstack の側は RST で切る(前述の TCP の項)
<a id="実効宛先が違う"></a>
- 実効宛先が違う:閉じてから開きます。
  セッションは閉じるときと同じ切り方で切れる
<a id="所属ルール-id-だけが違う"></a>
- 所属ルール ID だけが違う:何もしません。
  セッションは残る

この規則から、ルールの操作ごとの挙動が次のように導かれる。

<a id="enabled--false"></a>
- `enabled = false`:そのルールの全ポートが宣言から消えるので閉じます。
  `true` に戻すと開くだけで、切れるセッションはありません。
  無効にしたときに切ったセッションはポートを保持しないので、直後に `true` に戻しても待ち受けはすぐに開きます
<a id="target-の変更"></a>
- `target` の変更:全ポートの実効宛先が変わるので閉じ直す
<a id="範囲の伸縮"></a>
- 範囲の伸縮:差分のポートだけ開閉します。
  範囲をずらして同じポートの実効宛先が変わった場合は、そのポートだけ閉じ直す
<a id="ルールの分割と統合54-節controlbatchesmd54-ルールのバッチ操作のバッチで-1-世代として行う"></a>
- ルールの分割と統合([5.4 節](../control/batches.md#54-ルールのバッチ操作)のバッチで 1 世代として行う):ポートの実効宛先が変わらなければセッションは残り、所属ルール ID だけが移る

ルール 1 本の上限は、今までどおり、そのルールに所属するリスナーのセッション合計で判定します。
分割で移ったリスナーの既存セッションも、上限の判定では移動先のルールの数に入ります。
ルールごとの最低分([7a.10 節](../resource/admission.md#7a10-resource-guard-の再設計))は、そのルールの登録に数えるセッションの数で判定します。
セッションは、受け付けたときのルールの登録で数えます。
分割で所属ルール ID が変わったリスナーの既存セッションは、分割元のルールの登録が続くあいだ、最低分の判定では分割元で数え、移動先のルールでは数えません。
リスナーがその後に受け付けるセッションは、移動先のルールの登録で数えます。
ルールの登録が退役したとき(そのルールの新しいセッションを受け付けているリスナーが無くなったとき。
統合と名前の変更で消えるルール、削除、無効化、fail-closed を含む)、その登録のセッションのうち、今も新しいセッションを受け付けているリスナーが運ぶものは、そのリスナーの今のルールの登録で数えます。
したがって統合で消えたルールの既存セッションは統合先のルールで数え、分割の後に分割元のルールを削除すると、分割先のリスナーが運ぶ既存セッションは分割先のルールで数えます。
統合で合計が上限を超えた場合、既存セッションは追い出さず、期限切れで上限を下回るまで新規を捨てます。
