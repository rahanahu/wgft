# wgstack の dial の側

この文書は、`vpsd` のユーザー空間モードの netstack を gVisor から [wgstack](wgstack.md) に移すために、wgstack に加える dial の側の骨格を定めます。
所有者が 2026-10-31 にこの方向を仮に選びました。
未実装です。
構造の骨格をここで決め、値と細部は[実装の時に決めること](#実装の時に決めること)に残します。
所有者が 2026-10-31 に決めた点は[決めたこと](#決めたこと)に、残る点は[未決の点](#未決の点)に挙げます。
決めた点の方針は、小さく始めて、測ってから育てることです。

作業の順は次のとおりです([作業の順序](#作業の順序))。

1. wgstack の性能の第 2 段階を、今のラボのカーネル(6.1)で閉じます
2. リファクタリングと脆弱性の検査を、ラボのカーネルの更新、基準の取り直し、Linux の挙動の仕様と並行に行います
3. 核のファイルと UDP に触れる実装を、リファクタリングの後に始めます

参照の Linux は、第 2 段階が main に入った直後、dial の実装の前に、Debian 13 の trixie-backports の 7.2 のカーネルに移ります([決めたこと](#決めたこと))。
能動の open の Linux の挙動は、別の PR で書いている Linux の opener の挙動の仕様(v6.1 と v7.2 を扱います)にまとめます。
その仕様が入るまでは、RFC 9293 とこの文書の規則に従います。
この文書はその仕様を写さず、wgstack が従う規則の骨格だけを書きます。

## 目的と範囲

`vpsd` のユーザー空間モードは、公開側をホストのソケットで受け、gVisor の netstack 越しにエージェントへ dial します([ユーザー空間モード](../vps/userspace.md#63-ユーザー空間モード))。
この netstack には、エージェントの側と同じ gVisor 由来の既知の制限が残ります([上界に含めない保持点](memory-limits.md#中身の無い-segment-の処理待ち)、[短い障害の後の回復](../vps/userspace.md#63-ユーザー空間モード))。
目的は、`vpsd` の netstack も保持の上界を式で導ける wgstack にし、後で製品から gVisor を外せるようにすることです。

範囲は次のとおりです。

- 対象:`vpsd` のユーザー空間モードのトンネル(`internal/dataplane/userspace/utun`)です。
  エージェントの側の受動の open と待ち受けの挙動は変えません
- 開き方:TCP の能動の open を加えます。
  `vpsd` は netstack の上で TCP と UDP を待ち受けません
- UDP:接続した UDP のセッションを加えます
- ICMP:自分のアドレスへの echo への応答(エージェントの keepalive の ping の相手)と、ICMP の誤りの受け取りを使います
- アドレス:Device のアドレスは `10.200.0.1` の 1 つで、全エージェントのピアが 1 つの Device を分け合います

gVisor は、エージェントのユーザー空間モードの既定の netstack です。
Windows と macOS のエージェントも既定で gVisor を使い、1.x の間は選べるまま残ります。
このため、gVisor の待ち受けとの相互運用は、Linux と wgstack の待ち受けと並ぶ常の要件です。
gVisor を製品から外した後も、Linux、試験の側の台本、wgstack 自身と並ぶ、実装の違う試験の相手として残します。
[目標と制約](wgstack-performance.md#目標と制約)の gVisor との比で書いた目標はそのまま使います。

[不変条件](wgstack.md#不変条件)の I1 から I7 を `vpsd` の Device にも当てます。
I7 は、カーネルモードの `vpsd` が wgstack を作らず、そのコードがカーネルモードの経路で動かないことに当たります。

## TCP の能動の open

能動の open の規則は RFC 9293 とこの文書の規則に従い、別の PR で書いている Linux の opener の挙動の仕様が入った後はその仕様にも合わせます。
Linux と違う挙動を選ぶ点は、[期待した差](wgstack-verification.md#期待した差の一覧)に記録します。

### SYN-SENT の置き場

SYN-SENT の接続は接続の枠に置きます。
中継は dial の前に同時フロー数の枠を取るので、SYN-SENT の数は K で抑えられます。
疎通確認のように K に数えない dial には、K の外に小さな固定の枠を置き、満ちていれば dial は誤りを返します。
`vpsd` の Device の枠の数 N_c は、K と、この固定の枠の和です。
確立の処理は、握手の途中の行からではなく、交渉した値の組から始める形に分けます。
受動の open の確立もその形を通します。

### ポートと 4 つ組の選び方

一時ポートは RFC 6056 の乱数を使う選び方で選びます。
選んだ 4 つ組は、接続の表、TIME_WAIT の表、SYN-SENT の接続のどれとも衝突してはいけません。
公開側のクライアントが先に閉じる組では、`vpsd` が先に FIN を送って TIME_WAIT を持ちます。
このため、同じ宛先(エージェントの 1 つのポート)への接続の入れ替わりが速いと、その宛先への一時ポートが尽きえます。
尽きたときは dial が誤りを返し、数を数えて 1 分に 1 回までログに出します。
TIME_WAIT の 4 つ組を自分の側で使い直す規則を持つかどうかと、その条件は実装の時に決めます。

### SYN の再送と期限

最初の RTO は RFC 6298 の 1 秒で、再送ごとに倍にします。
呼び出し側の期限(今の `Backend.Dial` では 5 秒)が来るか、再送の回数の上限に達したら、dial は誤りを返します。
取り消した接続は RST を送らずに枠を返します。
後から届いた SYN-ACK は、どの接続にも当たらない segment として RST を受けます。
SYN を再送した接続の初期の輻輳の窓は、受動の open と同じく 1 segment です。

### SYN-SENT での RST と ACK

RFC 9293 3.10.7.3 の SYN-SENT の規則に従います。

- 受け入れられない ACK:SYN を確認しない ACK を持つ segment には、RST の印が無ければ RST を返して捨てます
- RST:受け入れられる ACK を持つ RST で接続を終え、dial は拒まれたことを表す誤りを返します。
  ACK を持たない RST は捨てます
- ICMP の誤り:SYN-SENT の間の Destination Unreachable は接続を終えない柔らかい誤りとします(RFC 1122 4.2.3.9)。
  dial は期限で終わります
- 同時の open:持ちません。
  SYN-SENT で ACK の無い SYN を受けたら、その dial を失敗させて枠を返します。
  RFC 9293 と Linux は SYN-RECEIVED に移るので、これは知った上での違いで、適合の試験では[期待した差](wgstack-verification.md#期待した差の一覧)にします。
  `vpsd` は netstack で待ち受けず、エージェントは `vpsd` の netstack へ dial しないので、正しい相手との間では起きません。
  起こせるのは鍵を持つエージェントだけで、そのエージェントは SYN に応えないことでも同じ dial を失敗させられるので、守りを弱めません

エージェントのユーザー空間モードは待ち受けの無いポートへの SYN に RST を返し、カーネルモードのエージェントは黙って捨てます([ユーザー空間モード](../vps/userspace.md#63-ユーザー空間モード)の宛先への試し接続の項)。
後者では dial が期限まで待ちます。

### client の側の option

SYN に MSS、SACK-permitted、timestamp、窓の scale を載せます。
並びは、別の PR で書いている Linux の opener の挙動の仕様が入った後に、その仕様に合わせます。
使うかどうかは SYN-ACK で決めます。

- MSS:SYN-ACK の値に従い、値 0 と欠落では 536 を使います
- 窓の scale:SYN-ACK が持たなければ、両方の向きで scale を使いません(RFC 7323 2.2)
- SACK:SYN-ACK が SACK-permitted を持つときだけ使います
- timestamp:SYN-ACK が持たなければ使いません。
  SYN-ACK の TSecr から最初の RTT を測ります

相手の待ち受けは、カーネルモードのエージェントの Linux、ユーザー空間モードのエージェントの gVisor と wgstack の 3 つです。
3 つとの相互運用を常の要件として[検証](#検証)で確かめます。

確立した後に重複した SYN-ACK が届いたら、ACK を返します。

### dial の誤りの約束

疎通確認は dial の誤りを `errors.Is` と `net.Error` の `Timeout()` で見分け、`server doctor` の probe がその文言を示します(`internal/vpsd/conncheck` の `friendlyDialErr`)。
到達の段の判定は、dial の後の読み取りが返す `io.EOF`、`ECONNRESET`、期限の誤りで決まります。
今の gVisor の dial は誤りを文字列にして返します。
wgstack の dial と接続は、次の誤りを返します。

| 場合 | 返す誤り |
|---|---|
| SYN-SENT で RST を受けた | `errors.Is` で `syscall.ECONNREFUSED` に当たる誤り |
| 期限か再送の上限 | `Timeout()` が真の `net.Error` |
| SYN-SENT の間の ICMP の誤り | 接続を終えないので、期限の誤りになります |
| SYN-SENT で ACK の無い SYN を受けた | 期限でも拒否でもない誤り |
| 一時ポートと疎通確認の枠の不足 | 期限でも拒否でもない誤り |
| 確立の後に RST を受けた後の読み書き | `errors.Is` で `syscall.ECONNRESET` に当たる誤り |
| 相手の FIN の後の読み取り | `io.EOF` |

ラボで、`server doctor` の probe の分類が 2 つのサーバの netstack で同じになることを確かめます。

## UDP の接続したセッション

`vpsd` は、公開側の送信元ごとに、エージェントへ接続した UDP を 1 つ作ります。
数は `WGFT_MAX_UDP_FLOWS`(既定 8192)まであります。

- 接続:一時ポートを選び、相手の 4 つ組に合う datagram だけを受け取ります。
  相手の違う datagram には Port Unreachable を返します。
  この絞り込みは、別のエージェントがほかのセッションのポートへ datagram を入れることも防ぎます
- 待ち:中継が型アサーションで探す `WaitReadable` を持ち、次の datagram が届くまでバッファを持たずに待てるようにします
- ICMP:相手からの Port Unreachable で、読み取りに誤りを返します。
  中継は読み取りの誤りでセッションを閉じます
- 受信の予算:今の UDP の予算は少数の待ち受けを前提にしています([UDP の受信の予算](udp-accounting.md#udp-の受信の予算))。
  chunk を endpoint ごとに 16 KiB で持つので、受信の 4 MiB では同時に datagram を持てる endpoint が 256 本程度までです。
  endpoint ごとの上限の 1/4 も、本数の多い構成では意味を持ちません。
  セッションの数に合わせて、chunk を endpoint の間で分け合う形か、より小さな単位で持つ形に作り直し、エージェントごとの上限([多くのエージェントが 1 つの Device を分け合うこと](#多くのエージェントが-1-つの-device-を分け合うこと))を加えます
- 送信の意味:中継は待ち受けごとに 1 つの読み取りのループから全セッションへ書き、`Write` の誤りでそのセッションを閉じます。
  今の gVisor の `Write` は送信の余地ができるまで待ち、エージェントの側の wgstack の `WriteTo` も予約できるまで待ちます。
  送信の予算は Device 全体で持つので、`vpsd` で `Write` が待つと、その待ち受けの全セッションが、別のピアのセッションも含めて止まります。
  送信の予算にもエージェントごとの上限を置きますが、上限に達した接続した UDP の `Write` が待つか、黙って捨てるか、誤りを返してセッションを閉じるかは未決です([未決の点](#未決の点))
- 会計の不整合:エージェントの側の[会計の不整合](udp-accounting.md#会計の不整合)と同じく、検出したらその Device の UDP を止め、TCP は止めず、最初の違反を保ちます。
  共有の Device では全エージェントの UDP が止まるので、wgstack の `vpsd` では、ログの 1 行に加えて、server の数えに載せ、`server doctor` の検査を失敗にします。
  自動では再起動しません。
  再起動は全エージェントの転送を切るので、運用者が判断します。
  gVisor の `vpsd` をログの行だけで知らせる今の扱いは変えません。
  `server doctor` と数えに加える面は公開のサーフェスへの加算なので、実装と同じ変更で互換性の文書に書きます

エージェントの待ち受けの挙動と上界は、作り直しの後も保ちます。

## 多くのエージェントが 1 つの Device を分け合うこと

すでにある隔離は次のとおりです。

- 送信元:WireGuard の AllowedIPs がピアごとの /32 に縛るので、ピアは別のピアのアドレスを名乗れません
- 流れ:TCP の 4 つ組と接続した UDP の絞り込みで、別のピアの流れに segment を入れられません
- ICMP の誤り:外側の送信元が引用の宛先と一致する誤りだけを受け入れます([ICMP の誤りの入口](packet-validation.md#icmp-の誤りの入口))
- フローの数:Resource Guard のルールごとの上限と最低分([7a.10 節](../resource/admission.md#7a10-resource-guard-の再設計))と、接続元ごとの上限が、同時フロー数を分けます。
  ルールはエージェントに属するので、K は実質でルールの単位に分かれています

残るのは、Device 全体の資源をあるピアが使い切り、別のピアの流れを妨げることです。
今の gVisor の `vpsd` も、出力の FIFO を分けないので同じ性質を持ちます。

| Device 全体の資源 | 1 つのピアが使い切ったときの影響 |
|---|---|
| UDP の受信と送信の予算 | 別のピアの UDP の datagram が捨てられるか、送信が待たされます |
| challenge ACK の token bucket と ICMP の誤りの速さ | 別のピアへの challenge ACK と ICMP の誤りが出なくなります |
| 再組み立ての表 | 別のピアの組み立ての途中が追い出されます |
| 制御の出力の輪 | 別のピアへの RST が捨てられます。設計は枠を返した後の RST の損失を受け入れています([出力](wgstack.md#出力)) |
| TIME_WAIT の表 | 古い行が追い出されるだけで、上界は崩れません |
| boost の枠 | 取れない接続は floor で続けます |
| 出力の組の間の配分 | 組の間の配分だけで、ピアの間の配分はありません |

隔離は、1 つの Device の中のエージェントごとの上限で行います。

- 上限を置く資源:1 つのエージェントが占めうる共有の資源、つまり UDP の送信と受信の予算、challenge ACK と ICMP の誤りの速さの bucket、再組み立ての表です。
  鍵はピアのアドレスです
- 上限の形:最初は「1 つのエージェントが使えるのは全体の決まった割合まで」という単純な形にします。
  割合の値は未決で、多くのエージェントでの測定の後に形を育てます
- TCP:Resource Guard のルールごとの上限ですでにエージェントの間に分かれているので、何も加えません
- ほかの資源:制御の出力の輪、TIME_WAIT の表、boost の枠、出力の組の間の配分は、上の表の影響を受け入れ、上限を置きません

ピアごとの Device は採りません。
入ってくる packet の宛先はどれも `10.200.0.1` なので、送信元のアドレスで振り分けることはできます。
しかし各 Device は作成の時に N_c から枠の配列と hash の表を確保するので、K をピアの間で分けない限り、表が K × A に比例し、Device 1 つの固定の費用([上界の式](wgstack.md#上界の式)の M_fix)も A に比例します。

## 敵対的な入力の模型

`vpsd` のユーザー空間モードでは、公開側のクライアントはホストのソケットに接続し、netstack の相手はエージェントだけです。
netstack に任意の packet を入れられるのは、WireGuard の鍵を持つエージェントか、そのホストを奪った者だけです。

公開側の入力は、次の形で間接に netstack に効きます。

- 新しい接続の速さ:公開側の接続ごとに dial が 1 つ起きます。
  Admission Policy と同時フロー数の上限が SYN-SENT の数を抑えます。
  エージェントが落ちている間は、各 dial が期限まで枠を持ちます
- データの量:公開側のクライアントの上りが netstack の送信の向きに、エージェントからの下りが受信の向きになります
- UDP のセッションの数:公開側の送信元ごとに接続した UDP が 1 つできます

鍵を持つ敵対的なエージェントが client の役に対して起こせることは、次のとおりです。

- 偽りの SYN-ACK:SYN-SENT の 4 つ組に合う SYN-ACK で、窓 0、極端な MSS、大きな窓の scale を返します
- 同時の open:SYN-SENT の 4 つ組に合う SYN でその dial を失敗させます。
  SYN に応えないことでも同じ結果になるので、新しい害を加えません
- 読まない相手:確認だけを返して受信しません
- 共有の資源の消費:共有の資源を使い切って、別のエージェントの流れを妨げます

今の設計は、エージェントを信頼できない場合に `vpsd` をカーネルモードで動かすよう求めます([ユーザー空間モード](../vps/userspace.md#63-ユーザー空間モード))。
wgstack は中身の無い segment の処理待ちを持たないので、その理由の 1 つが構造で消えます。
この要求は今は緩めません。
server の側の脆弱性の検査と、多くのエージェントでの隔離の測定の後に、緩めるかを考え直します。

## 上界の式の変わる項

今の `vpsd` の上界は [server のメモリの上界](memory-server.md#プロセス全体のメモリの上界)の表の和です。
wgstack に替えると、次の項が変わります。

| 今の項 | wgstack での扱い |
|---|---|
| [TCP のフロー](memory-server.md#tcp-のフロー-1-本の上界)(1,598 KiB × K)と TCP の boost | netstack の分は N_c × (c_conn + f_s + f_r + r_f + h_f) と B × (d_s + d_r + d_rec + d_h) に替わります。今の固定の分の 74 KiB は中継のコピーのバッファを含み、wgstack の式は中継と `internal/netpipe` を数えないので、中継の側の K に比例する項は残します |
| wgstack の固定の構造 | M_fix を加えます。K が 2048 のとき約 25.6 MiB です |
| [中身の無い ACK の処理待ち](memory-server.md#中身の無い-ack-の処理待ちの上界) | 無くなります |
| 閉じた後の netstack の TCP の接続 | M × c_tw。M は `vpsd` の入れ替わりに合わせて決め直します |
| netstack の出力のキュー(64 MiB) | 今のキューは UDP の出力も持ちます。Q_ctl × s_ctl と、作り直した UDP の送信の予算の項(今の式の M_udp_tx)に替わります |
| UDP の受信の会計 | 作り直した UDP の受信の予算の項に替わります |
| UDP のセッション(4.5 KiB × U) | gVisor で測った値なので、wgstack で測り直します |
| IPv4 の再組み立て | M_frag。ピアごとの待機の分の扱いを確かめ直します |
| goroutine のスタック(TCP の 24 KiB × K) | gVisor の接続を含む推定なので、wgstack で導き直します |

握手の途中の表と accept の待ち行列の項は、`vpsd` の Device では 0 か最小になります。
エージェントごとの上限は全体の予算の内側の割合なので、エージェントの数 A に比例する保持の項を加えません。
上限の管理に要る小さな構造は、エージェントの数で決まるので式に数えます。
wireguard-go のピアごとのキューとエージェントのハートビートの受信の項は変わらず、A に比例する大きな項として残ります。
上界は、エージェントの側と同じく、上限の設定値ではなく実際に持てる量で数えます。
公開している `vpsd` のホストのメモリの要件([ユーザー空間モード](../vps/userspace.md#63-ユーザー空間モード)の約 12.7 GiB)は netstack によって変わるので、netstack ごとに示し直します。

## 尽きたときの動作

[尽きたときの動作](wgstack.md#尽きたときの動作)の方針(新しい保持を拒み、既存の保持を追い出さない)をそのまま使います。
dial の側で加わるものは次のとおりです。

| 資源 | 尽きたときの動作 |
|---|---|
| 一時ポート | dial が誤りを返します |
| 疎通確認の枠 | 疎通確認の dial が誤りを返します |
| 接続した UDP の受信の予算とエージェントごとの受信の上限 | datagram を捨てて、ICMP を返しません。エージェントごとの上限はそのエージェントの datagram だけを捨てます |
| 接続した UDP の送信の予算とエージェントごとの送信の上限 | 未決の送信の意味に従います([未決の点](#未決の点)) |

## 設定と選択

サーバの netstack は `WGFT_NETSTACK` で受け取り、フラグ `--netstack` はその別名です([設定の渡し方](../security/configuration.md#11a-設定の渡し方))。
値は `gvisor` と `wgstack` です。
名前は、`WGFT_MODE` や `WGFT_MTU` のような接頭辞の無い server の設定にそろえます。
エージェントの設定は `WGFT_AGENT_*` で、エージェントは `WGFT_NETSTACK` を読みません。
規則は、エージェントの[実装の選択](wgstack.md#実装の選択)と同じです。

- 既定:省略と空の値は `gvisor` で、1.x の間は変えません
- 明示:値を指定したときだけ wgstack を使い、環境から推測しません
- 知らない値:設定の誤りとして終了コード 3 で止めます
- モード:`WGFT_MODE=userspace` のときだけ使います。
  カーネルモードでは値を使わず、値があれば使わない旨を英語の 1 行で出して起動を続けます。
  黙って無視しません
- 作成の失敗:wgstack の作成に失敗しても gVisor に切り替えません
- 起動ログ:有効な設定の印字に値と出所が載ります。
  wgstack のときは、実験的な選択肢であることを英語の 1 行で出します
- トンネルの宣言:wgstack の Device は作成の時に表を確保するので、トンネルの宣言は K、U、疎通確認の枠の数を受け取ります。
  今の `utun` の宣言はこれらを持ちません

- 実験的な扱い:`wgstack` は実験的な選択肢です。
  起動の 1 行で知らせ、互換性の文書に、選んだときの転送の品質と資源の挙動を保証に含めないと書きます
- 既定の変更:既定を `wgstack` に替えるには所有者の決定が要り、1.x の minor の版でリリースノートで知らせます。
  エージェントと同じく、`gvisor` を明示すれば元の実装を選べる状態を保ちます

`WGFT_NETSTACK` の名前と値は公開のサーフェスになるので、[設定の互換性](../compatibility/surfaces.md)の対象になります。
設定の文書と互換性の文書への記載は、実装と同じ変更で行います。

## 検証

[wgstack の検証](wgstack-verification.md)の原則(Linux が参照、試験の書き手の分離、Linux で先に通すこと、決定的な実行)を dial の側にも当てます。
参照の Linux は、移った後のラボのカーネル(Debian 13 の trixie-backports の 7.2)です。
[wgstack の検証](wgstack-verification.md)の[参照の Linux の設定](wgstack-verification.md#参照の-linux-の設定)と[試験の置き場所と DUT](wgstack-verification.md#試験の置き場所と-dut)は、ラボのカーネルを移す時に直します。
第 2 段階は今の 6.1 で閉じるので、それまでは 6.1 の記述のままです。

- 適合の試験:`Dial` と `DialUDP` を持つ DUT の任意の面を加えます。
  参照の opener は Linux で、ラボの network namespace の TUN の中から Linux のソケットが接続し、試験の側が待ち受けの役で SYN を受けます。
  台本の期待は、別の PR で書いている Linux の opener の挙動の仕様に従い、それが入るまでは RFC 9293 とこの文書の規則に従います。
  台本は、SYN の option と並び、SYN の再送の間隔と打ち切り、option の無い SYN-ACK、窓の scale の無い SYN-ACK、MSS 0 と欠落、窓 0 の SYN-ACK、誤った ACK への RST、RST による拒否、SYN-SENT の間の ICMP、同時の open、データを持つ SYN-ACK、確立した後の重複の SYN-ACK、[dial の誤りの約束](#dial-の誤りの約束)を扱います。
  同時の open の台本では、wgstack の dial の失敗を期待した差にします。
  データ、窓、再送、終わり方の台本は、確立の段を能動の open に替えて同じ台本を流します
- 相互運用:wgstack の opener を、Linux、gVisor、wgstack の待ち受けにそれぞれつなぐ試験を常に流します。
  gVisor は比べる DUT であるだけでなく、opener が必ずつながる相手です
- 多くのピアの台本:試験の側が複数の送信元のアドレスを持ち、同じ宛先への一時ポートの選び方、接続した UDP の絞り込み、別のピアの流れを引用する ICMP の誤り、エージェントごとの上限を確かめます
- fuzzing:`FuzzCore` のアプリケーションの操作に `Dial`、`DialUDP`、取り消しを加えます。
  SYN に応える相手の segment の列を任意にする fuzz target と、送信元のアドレスが複数の packet の列で隔離の不変条件を確かめる fuzz target を加えます
- 敵対的な保持の試験:偽りの SYN-ACK、エージェントが落ちている間の dial の洪水、多数の UDP のセッション、1 つのピアによる共有の資源の洪水で、保持が上界で止まり、入力が止まった後に戻ることを確かめます
- qbench:wgstack を client にできるようにします。
  DUT が opener になるセル(送る向きと受ける向き、損失と途絶の下の SYN の再送、接続の速さと確立までの遅れ)を加え、Linux、gVisor、wgstack を相手に並べます
- ラボ:`lab/lab` にサーバの netstack の切り替えを加え、ユーザー空間のサーバの確認を両方の netstack で流します。
  gVisor の閉じた後の表を前提にした確認は書き直します。
  `server doctor` の probe の分類を両方の netstack で確かめます。
  多くのエージェントで隔離を測り、エージェントごとの上限の形と値の材料にします。
  エージェントのメモリの確認(`lab/agentmem.sh`)と同じ形で、サーバのメモリの確認を加えます。
  負荷は、敵対的なエージェントと、多数の UDP のセッションです
- 実機:ステージングの環境で長く動かして確かめるまで、既定を変えません

## 作業の順序

性能の第 2 段階を今のラボのカーネルで閉じた後、リファクタリングと脆弱性の検査を、ラボのカーネルの更新、基準の取り直し、Linux の挙動の仕様と並行に行います。
核の実装は、リファクタリングの後に始めます。

リファクタリングと検査と並行に進めるものは次のとおりです。

- 骨格の詰め:この文書の未決の点の材料を集めます
- 適合の試験の面と台本:`Dial` を `internal/tcpharness` の任意の DUT の面にし、Linux の opener の DUT、能動の open と多くのピアの台本を書きます。
  試験の書き手が担当します。
  wgstack の DUT の `Dial` は核の実装を待ちます
- qbench の client の面:client を差し替えられる形に整えます
- 中継の試験の dial の相手:`vpsd` の役で `internal/nettun` の dial を名指す試験を、dial する相手の interface の後ろに隠します。
  リファクタリングが中継の試験か `internal/nettun` に触れるなら、範囲の境目を先に決めます
- utun の面:`utun` の中で netstack を非公開の interface の後ろに置きます。
  エージェントのトンネルの形に合わせます
- ラボの配線:`WGFT_NETSTACK` を渡すサーバの netstack の切り替えを、値が gVisor だけの状態で入れます
- 基準の記録:任意で、gVisor のサーバのメモリの確認を先に作り、比べる基準を取ります

リファクタリングの後に始めるものは次のとおりです。

- 核のファイル:SYN-SENT、確立の分け方、一時ポート、dial の誤りの型は `internal/wgstack` の TCP の核を変えます
- UDP:接続した UDP、予算の作り直し、エージェントごとの上限は UDP と出力の組を変えます
- 上界:上界の式と会計を変えます
- 切り替え:`utun` を wgstack に切り替え、`WGFT_NETSTACK` を加えます

dial と多くのピアは攻撃の面を変えるので、検査の最中には入れません。
入れた後の分は、別の検査の範囲にします。

## 決めたこと

所有者が 2026-10-31 に次の点を決めました。

- 参照の Linux:Debian 13 と trixie-backports の 7.2 のカーネルに移ります。
  版はラボの基の image の snapshot で固定して記録します。
  移すのは第 2 段階が main に入った直後で、dial の実装の前です
- 同時の open:持ちません。
  SYN-SENT で ACK の無い SYN を受けた dial は失敗します([SYN-SENT での RST と ACK](#syn-sent-での-rst-と-ack))
- 設定:`WGFT_NETSTACK`(`--netstack`)で、`WGFT_MODE=userspace` のときだけ使い、既定は 1.x の間 `gvisor` です。
  `wgstack` は実験的な選択肢で、既定の変更は所有者の決定とリリースノートを伴う 1.x の minor の版で行います([設定と選択](#設定と選択))
- エージェントの間の隔離:1 つの Device の中で、1 つのエージェントが占めうる共有の資源にエージェントごとの上限を置きます。
  TCP には加えず、ピアごとの Device は採りません([多くのエージェントが 1 つの Device を分け合うこと](#多くのエージェントが-1-つの-device-を分け合うこと))
- 信頼しないエージェント:エージェントを信頼できない場合に `vpsd` をカーネルモードにする要求は、今は緩めません([敵対的な入力の模型](#敵対的な入力の模型))
- 共有の Device の会計の不整合:ログの 1 行、server の数え、`server doctor` の検査の失敗で知らせ、自動では再起動しません([UDP の接続したセッション](#udp-の接続したセッション))

## 未決の点

- 接続した UDP の送信の意味:エージェントごとの上限か全体の予算に達したときに、`Write` が待つか、黙って捨てるか、誤りでセッションを閉じるか
- エージェントごとの上限の値:各資源で 1 つのエージェントが使える割合と、測った後の形
- server の数えと `server doctor` の検査の形:会計の不整合を載せる管理用 API の欄と検査の名前
- `WGFT_AGENT_NETSTACK=gvisor` の扱い:gVisor を製品から外す時に、拒否か別名かを決めます。
  どちらも値の意味の変更なので、メジャーの版と結び付けます
