# wgstack の dial の側

この文書は、`vpsd` のユーザー空間モードの netstack を gVisor から [wgstack](wgstack.md) に移すために、wgstack に加える dial の側の骨格を定めます。
所有者が 2026-10-31 にこの方向を仮に選びました。
未実装です。
実装の順は、wgstack の性能の第 2 段階を閉じ、その後のリファクタリングと脆弱性の検査を終えてから、核のファイルと UDP に触れる部分を始めます。
核に触れない部分は、リファクタリングと検査と並行に進めます([作業の順序](#作業の順序))。
構造の骨格をここで決め、値と細部は[実装の時に決めること](#実装の時に決めること)に残します。
所有者が決める点は[所有者が決めること](#所有者が決めること)に挙げます。

## 目的と範囲

`vpsd` のユーザー空間モードは、公開側をホストのソケットで受け、gVisor の netstack 越しにエージェントへ dial します([ユーザー空間モード](../vps/userspace.md#63-ユーザー空間モード))。
この netstack には、エージェントの側と同じ gVisor 由来の既知の制限が残ります([上界に含めない保持点](memory-limits.md#中身の無い-segment-の処理待ち)、[短い障害の後の回復](../vps/userspace.md#63-ユーザー空間モード))。
目的は、`vpsd` の netstack も保持の上界を式で導ける wgstack にし、後で製品から gVisor を外せるようにすることです。

範囲は次のとおりです。

- 対象:`vpsd` のユーザー空間モードのトンネル(`internal/dataplane/userspace/utun`)です。
  エージェントの側の受動の open と待ち受けの挙動は変えません
- 開き方:TCP の能動の open を加えます。
  `vpsd` は netstack の上で TCP と UDP を待ち受けません
- UDP:接続した UDP のセッションを加えます
- ICMP:自分のアドレスへの echo への応答(エージェントの keepalive の ping の相手)と、ICMP の誤りの受け取りを使います
- アドレス:Device のアドレスは `10.200.0.1` の 1 つで、全エージェントのピアが 1 つの Device を分け合います

gVisor は、製品から外した後も試験の相手として残します。
Linux、試験の側の台本、wgstack 自身と並ぶ、実装の違う相手の 1 つです。
このため、[目標と制約](wgstack-performance.md#目標と制約)の gVisor との比で書いた目標はそのまま使います。
`WGFT_AGENT_NETSTACK=gvisor` の扱い(拒否か別名か)は、gVisor を製品から外す時に決めます。

[不変条件](wgstack.md#不変条件)の I1 から I7 を `vpsd` の Device にも当てます。
I7 は、カーネルモードの `vpsd` が wgstack を作らず、そのコードがカーネルモードの経路で動かないことに当たります。

## vpsd が netstack に求めること

| 使う所 | 今の実装 | 求める機能 |

| 中継(UDP) | 同じ `Backend.Dial` の `udp` | 接続した UDP。`WaitReadable` と、ICMP の誤りで読み取りに誤りを返すこと |

| 疎通確認 | `internal/vpsd/conncheck` が同じ `Dial` を使います。K に数えません([TCP のフロー 1 本の上界](memory-server.md#tcp-のフロー-1-本の上界)) | 能動の open。K の外の小さな枠 |
| エージェントの keepalive の ping | エージェントが `vpsd` のアドレスへ echo を送ります | echo への応答 |

## TCP の能動の open

### SYN-SENT の置き場

SYN-SENT の接続は接続の枠に置きます。
中継は dial の前に同時フロー数の枠を取るので、SYN-SENT の数は K で抑えられます。
疎通確認のように K に数えない dial には、K の外に小さな固定の枠を置き、満ちていれば dial は誤りを返します。
`vpsd` の Device の枠の数 N_c は、K と、この固定の枠の和です。
確立の処理は、握手の途中の行からではなく、交渉した値の組から始める形に分けます。
受動の open の確立もその形を通します。

### ポートと 4 つ組の選び方

一時ポートは RFC 6056 の乱数を使う選び方で選びます。
選んだ 4 つ組は、接続の表、TIME_WAIT の表、SYN-SENT の接続のどれとも衝突してはいけません。
公開側のクライアントが先に閉じる組では、`vpsd` が先に FIN を送って TIME_WAIT を持ちます。
このため、同じ宛先(エージェントの 1 つのポート)への接続の入れ替わりが速いと、その宛先への一時ポートが尽きえます。
尽きたときは dial が誤りを返し、数を数えて 1 分に 1 回までログに出します。
TIME_WAIT の 4 つ組を自分の側で使い直す規則を持つかどうかと、その条件は実装の時に決めます。

### SYN の再送と期限

最初の RTO は RFC 6298 の 1 秒で、再送ごとに倍にします。
呼び出し側の期限(今の `Backend.Dial` では 5 秒)が来るか、再送の回数の上限に達したら、dial は誤りを返します。
取り消した接続は RST を送らずに枠を返します。
後から届いた SYN-ACK は、どの接続にも当たらない segment として RST を受けます。
SYN を再送した接続の初期の輻輳の窓は、受動の open と同じく 1 segment です。

### SYN-SENT での RST と ACK

RFC 9293 3.10.7.3 の SYN-SENT の規則に従います。

- 受け入れられない ACK:SYN を確認しない ACK を持つ segment には、RST の印が無ければ RST を返して捨てます
- RST:受け入れられる ACK を持つ RST で接続を終え、dial は拒まれたことを表す誤りを返します。
  ACK を持たない RST は捨てます
- ICMP の誤り:SYN-SENT の間の Destination Unreachable を柔らかい誤りとして覚えて期限の誤りに添えるかは、実装の時に決めます

エージェントのユーザー空間モードは待ち受けの無いポートへの SYN に RST を返し、カーネルモードのエージェントは黙って捨てます([ユーザー空間モード](../vps/userspace.md#63-ユーザー空間モード)の宛先への試し接続の項)。
後者では dial が期限まで待ちます。

### client の側の option

SYN に MSS、SACK-permitted、timestamp、窓の scale を Linux と同じ並びで載せます。
使うかどうかは SYN-ACK で決めます。

- MSS:SYN-ACK の値に従い、値 0 と欠落では 536 を使います
- 窓の scale:SYN-ACK が持たなければ、両方の向きで scale を使いません(RFC 7323 2.2)
- SACK:SYN-ACK が SACK-permitted を持つときだけ使います
- timestamp:SYN-ACK が持たなければ使いません。
  SYN-ACK の TSecr から最初の RTT を測ります

相手の待ち受けは、カーネルモードのエージェントの Linux、ユーザー空間モードのエージェントの wgstack、更新の途中の古い版の gVisor の 3 つです。
3 つとの相互運用を[検証](#検証)で確かめます。

確立した後に重複した SYN-ACK が届いたら、ACK を返します。

## UDP の接続したセッション

`vpsd` は、公開側の送信元ごとに、エージェントへ接続した UDP を 1 つ作ります。
数は `WGFT_MAX_UDP_FLOWS`(既定 8192)まであります。

- 接続:一時ポートを選び、相手の 4 つ組に合う datagram だけを受け取ります。
  相手の違う datagram には Port Unreachable を返します。
  この絞り込みは、別のエージェントがほかのセッションのポートへ datagram を入れることも防ぎます
- 待ち:中継が型アサーションで探す `WaitReadable` を持ち、次の datagram が届くまでバッファを持たずに待てるようにします。
  持たない接続には、中継がセッションごとに最大長のバッファを持ち続けます
- ICMP:相手からの Port Unreachable で、読み取りに誤りを返します。
  中継は読み取りの誤りでセッションを閉じます
- 予算:今の UDP の予算は少数の待ち受けを前提にしています([UDP の受信の予算](udp-accounting.md#udp-の受信の予算))。
  chunk を endpoint ごとに 16 KiB で持つので、受信の 4 MiB では同時に datagram を持てる endpoint が 256 本程度までです。
  endpoint ごとの上限の 1/4 も、本数の多い構成では意味を持ちません。
  セッションの数に合わせて、chunk を endpoint の間で分け合う形か、より小さな単位で持つ形に作り直し、ピアごとの予算([多くのエージェントが 1 つの Device を分け合うこと](#多くのエージェントが-1-つの-device-を分け合うこと))と合わせて決めます
- 会計の不整合:今と同じく、検出したらその Device の UDP を止めます

エージェントの待ち受けの挙動と上界は、作り直しの後も保ちます。

## 多くのエージェントが 1 つの Device を分け合うこと

すでにある隔離は次のとおりです。

- 送信元:WireGuard の AllowedIPs がピアごとの /32 に縛るので、ピアは別のピアのアドレスを名乗れません
- 流れ:TCP の 4 つ組と接続した UDP の絞り込みで、別のピアの流れに segment を入れられません
- ICMP の誤り:外側の送信元が引用の宛先と一致する誤りだけを受け入れます([ICMP の誤りの入口](packet-validation.md#icmp-の誤りの入口))

残るのは、Device 全体の資源をあるピアが使い切り、別のピアの流れを妨げることです。
今の gVisor の `vpsd` も、出力の FIFO を分けないので同じ性質を持ちます。

| Device 全体の資源 | 1 つのピアが使い切ったときの影響 |
|---|---|
| UDP の受信と送信の予算 | 別のピアの UDP の datagram が捨てられます |
| challenge ACK の token bucket と ICMP の誤りの速さ | 別のピアへの challenge ACK と ICMP の誤りが出なくなります |
| 再組み立ての表 | 別のピアの組み立ての途中が追い出されます |
| 制御の出力の輪 | 別のピアへの RST が捨てられます。設計は枠を返した後の RST の損失を受け入れています([出力](wgstack.md#出力)) |
| TIME_WAIT の表 | 古い行が追い出されるだけで、上界は崩れません |
| boost の枠 | 取れない接続は floor で続けます |
| 出力の組の間の配分 | 組の間の配分だけで、ピアの間の配分はありません |

隔離の形は 2 つ考えられます。

- 1 つの Device の中のピアごとの予算:ピアのアドレスを鍵に、上の資源にピアごとの上限か最低分を置きます。
  固定の費用はピアの数にあまり比例しません
- ピアごとの Device:宛先のアドレスで振り分けて、ピアごとに Device を持ちます。
  隔離は構造で決まりますが、Device 1 つの固定の費用([上界の式](wgstack.md#上界の式)の M_fix)がピアの数に比例します

どの資源をどの深さで分けるかは、所有者が決めます。

## 敵対的な入力の模型

`vpsd` のユーザー空間モードでは、公開側のクライアントはホストのソケットに接続し、netstack の相手はエージェントだけです。
netstack に任意の packet を入れられるのは、WireGuard の鍵を持つエージェントか、そのホストを奪った者だけです。

公開側の入力は、次の形で間接に netstack に効きます。

- 新しい接続の速さ:公開側の接続ごとに dial が 1 つ起きます。
  Admission Policy と同時フロー数の上限が SYN-SENT の数を抑えます。
  エージェントが落ちている間は、各 dial が期限まで枠を持ちます
- データの量:公開側のクライアントの上りが netstack の送信の向きに、エージェントからの下りが受信の向きになります
- UDP のセッションの数:公開側の送信元ごとに接続した UDP が 1 つできます

鍵を持つ敵対的なエージェントが client の役に対して起こせることは、次のものです。

- SYN-SENT の 4 つ組に合う SYN-ACK の偽り(窓 0、極端な MSS、大きな窓の scale)
- 同時の open の SYN
- 確認だけを返して受信しない相手
- 共有の資源を使い切って、別のエージェントの流れを妨げること

今の設計は、エージェントを信頼できない場合に `vpsd` をカーネルモードで動かすよう求めます([ユーザー空間モード](../vps/userspace.md#63-ユーザー空間モード))。
wgstack は中身の無い segment の処理待ちを持たないので、その理由の 1 つが構造で消えます。
この要求を緩めるかは、[検証](#検証)の後に決めます。

## 上界の式の変わる項

今の `vpsd` の上界は [server のメモリの上界](memory-server.md#プロセス全体のメモリの上界)の表の和です。
wgstack に替えると、次の項が [wgstack の上界の式](wgstack.md#上界の式)の項に置き換わります。

| 今の項 | wgstack での扱い |
|---|---|
| [TCP のフロー](memory-server.md#tcp-のフロー-1-本の上界)と TCP の boost | N_c × (c_conn + f_s + f_r + r_f + h_f) と B × (d_s + d_r + d_rec + d_h)。N_c は K と疎通確認の枠の和です |
| [中身の無い ACK の処理待ち](memory-server.md#中身の無い-ack-の処理待ちの上界) | 無くなります |
| 閉じた後の netstack の TCP の接続 | M × c_tw。M は `vpsd` の入れ替わりに合わせて決め直します |
| netstack の出力のキュー | Q_ctl × s_ctl。接続と行の出力は待ち行列を持ちません |
| UDP の受信の会計 | 作り直した UDP の予算の項と、セッションの数 U に比例する管理の構造の項 |
| IPv4 の再組み立て | M_frag。ピアごとの待機の分の扱いを確かめ直します |

握手の途中の表と accept の待ち行列の項は、`vpsd` の Device では 0 か最小になります。
ピアごとの予算を置くなら、エージェントの数 A に比例する項が加わります。
wireguard-go のピアごとのキューとエージェントのハートビートの受信の項は変わらず、A に比例する大きな項として残ります。
上界は、エージェントの側と同じく、上限の設定値ではなく実際に持てる量で数えます。

## 尽きたときの動作

[尽きたときの動作](wgstack.md#尽きたときの動作)の方針(新しい保持を拒み、既存の保持を追い出さない)をそのまま使います。
dial の側で加わるのは次のものです。

| 資源 | 尽きたときの動作 |
|---|---|
| 一時ポート | dial が誤りを返します |
| 疎通確認の枠 | 疎通確認の dial が誤りを返します |
| 接続の UDP の予算とピアごとの予算 | datagram を捨てて、ICMP を返しません。ピアごとの予算はそのピアの datagram だけを捨てます |

## 設定と選択

サーバの netstack は、エージェントの[実装の選択](wgstack.md#実装の選択)と同じ規則で選びます。

- 値を指定したときだけ wgstack を使い、環境から推測しません
- 知らない値は、設定の誤りとして終了コード 3 で止めます
- カーネルモードでは値を使わず、値があれば使わない旨を英語の 1 行で出して起動を続けます
- wgstack の作成に失敗しても gVisor に切り替えません
- 起動ログの有効な設定の印字に値と出所が載ります

設定の名前と既定は所有者が決めます。
名前は公開のサーフェスになるので、[設定の互換性](../compatibility/surfaces.md)の対象になります。

## 検証

[wgstack の検証](wgstack-verification.md)の原則(Linux が参照、試験の書き手の分離、Linux で先に通すこと、決定的な実行)を dial の側にも当てます。

- 適合の試験:DUT の面に `Dial` と `DialUDP` を加えます。
  参照の opener は Linux で、ラボの network namespace の TUN の中から Linux のソケットが接続し、試験の側が待ち受けの役で SYN を受けます。
  gVisor の DUT は `internal/nettun` の dial で、違う実装の相手として同じ台本に流します。
  台本は、SYN の option と並び、SYN の再送の間隔と打ち切り、option の無い SYN-ACK、窓の scale の無い SYN-ACK、MSS 0 と欠落、窓 0 の SYN-ACK、誤った ACK への RST、RST による拒否、SYN-SENT の間の ICMP、同時の open、データを持つ SYN-ACK、確立した後の重複の SYN-ACK を扱います。
  データ、窓、再送、終わり方の台本は、確立の段を能動の open に替えて同じ台本を流します
- 多くのピアの台本:試験の側が複数の送信元のアドレスを持ち、同じ宛先への一時ポートの選び方、接続した UDP の絞り込み、別のピアの流れを引用する ICMP の誤り、ピアごとの予算を確かめます
- fuzzing:`FuzzCore` のアプリケーションの操作に `Dial`、`DialUDP`、取り消しを加えます。
  SYN に応える相手の segment の列を任意にする fuzz target と、送信元のアドレスが複数の packet の列で隔離の不変条件を確かめる fuzz target を加えます
- 敵対的な保持の試験:偽りの SYN-ACK、エージェントが落ちている間の dial の洪水、多数の UDP のセッション、1 つのピアによる共有の資源の洪水で、保持が上界で止まり、入力が止まった後に戻ることを確かめます
- qbench:wgstack を client にでき、ホストで gVisor 以外の client でも回せるようにします。
  DUT が opener になるセル(送る向きと受ける向き、損失と途絶の下の SYN の再送、接続の速さと確立までの遅れ)を加えます。
  Linux、gVisor、wgstack を相手に並べます
- ラボ:`lab/lab` にサーバの netstack の切り替えを加え、ユーザー空間のサーバの確認を両方の netstack で流します。
  gVisor の閉じた後の表を前提にした確認は書き直します。
  エージェントのメモリの確認(`lab/agentmem.sh`)と同じ形で、サーバのメモリの確認を加えます。
  負荷は、敵対的なエージェントと、多数の UDP のセッションです
- 実機:ステージングの環境で長く動かして確かめるまで、既定を変えません

## 作業の順序

性能の第 2 段階を閉じ、その後にリファクタリングと脆弱性の検査を行います。

リファクタリングと検査と並行に進めるもの:

- 骨格の詰め:この文書の未決の点の材料を集めること
- 適合の試験:DUT の `Dial` の面、Linux の opener の DUT、能動の open と多くのピアの台本。
  `internal/tcpharness` の中で閉じ、試験の書き手が担当します
- qbench の client の面:client を差し替えられる形に整えます
- 中継の試験の dial の相手:`vpsd` の役で `internal/nettun` の dial を名指す試験を、dial する相手の interface の後ろに隠します
- ラボの配線:サーバの netstack の切り替えを、値が gVisor だけの状態で入れます

検査の後に始めるもの:

- 核のファイルの変更:SYN-SENT、確立の分け方、一時ポートは `internal/wgstack` の TCP の核を変えます
- UDP の作り直しとピアごとの予算:UDP と出力の組を変えます
- 上界の式と会計の変更
- `utun` の wgstack への切り替えと設定の追加

dial と多くのピアは攻撃の面を変えるので、検査の最中には入れません。
入れた後の分は、別の検査の範囲にします。

## 所有者が決めること

- 同時の open:RFC 9293 どおり SYN-RCVD に移るか、持たずに[期待した差](wgstack-verification.md#期待した差の一覧)にするか。
  `vpsd` は netstack で待ち受けず、エージェントは `vpsd` の netstack へ dial しないので、正しい相手との間では起きません
- サーバの netstack の設定:名前と既定の値
- ピアごとの隔離の深さ:どの共有の資源をピアごとに分けるか、1 つの Device の中の予算か、ピアごとの Device か

## 実装の時に決めること

- 一時ポートの幅と、TIME_WAIT の 4 つ組を自分の側で使い直す規則
- SYN の再送の回数の上限
- 疎通確認の枠の数
- SYN-SENT の間の ICMP の誤りの扱い
- UDP の chunk の単位、予算の値、ピアごとの上限と最低分の値
- `vpsd` の Device の M、Q_ctl などの表の大きさ
