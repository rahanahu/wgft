# メモリの上界 (N3)

この文書は、推奨の構成 U のプロセス全体のメモリの上界を式で示し、全体と unit ごとの予算、固定の置き場と大きさの区分、尽きた時の規則を定めます。
未採用の提案です([提案の索引](README.md))。
上界の考え方は今の設計と同じく、上限の設定値ではなく実際に持てる量で数えます([上界の式の写し方](../../v2/wgstack-rs.md#上界の式の写し方))。
I1 から I7 の[不変条件](../../userspace/wgstack.md#不変条件)をそのまま守ります。

## 上界の原則

- 予算の印と置き場の枠を 1 つの値にします。
  byte を持つことと、その byte の予算を持つことが同じ値の所有になり、二重の数えと数え漏れが型で起きにくくなります(設計判断)
- 置き場はすべて起動の時に容量を決め、後から大きくしません。
  例外は今と同じく、予約の内側でだけ確保する 16 KiB の chunk と、流れごとの中継の状態です
- 予算は全体で 1 つ持ち、unit は credit として一部を借ります。
  credit の補充と返却はデータの経路の外 (実行の終わり) で行います
- 接続は unit を移らず、chunk と中継のバッファは unit の状態の置き場に返るので、unit をまたぐ解放は起きません
- executor の間の輪は、捨ててよいデータの輪と捨てない知らせの輪に分け、捨てない輪は容量を知らせの数の上界から決めます([front と unit の間の知らせ](ownership.md#front-と-unit-の間の知らせ))
- データの経路で packet ごとにヒープを確保しません

## 核の作り直し

今の核の型は、作成の時に 65,536 行の待ち受けの表と UDP の endpoint の表を必ず確保します (`crates/wgft-wgstack/src/tcp/listen.rs` の `PortTable::new`)。
上界の表では、1 つの核あたり `listeners` が 1.0 MiB、`udp_endpoints` が 2.3 MiB、ポートの知らせを含む `events` が 0.6 MiB です([wgstack の上界の表](../../v2/wgstack-bound.md))。
U では核を front の核と unit の核に分け、ポートで決まる表は front の核だけが持つように作り直します(設計判断)。
unit の核が持つのは、自分の枠の数で決まる配列と、小さな制御の輪と出力の list だけです。

## 上界の式

H は helper の数、M は unit の数で、どちらも利用できる CPU の数から決まります([CPU の数ごとの動かし方](performance.md#cpu-の数ごとの動かし方))。

```text
M_proc = M_base
       + M_fix
       + N_c × (f_s + f_r + r_f + h_f)
       + G
       + M_udp_rx + M_udp_tx + M_frag + N_ping × c_ping
       + M_ct + M_pt + M_tx,front + M_dev
       + M_relay
       + Σ_{u=1}^{M} M_unit,u
       + Σ_{h=1}^{H} M_helper,h
       + M_ring
```

| 項 | 中身 | 今の式との関係 |
|---|---|---|
| M_base | 実行ファイル、制御プレーン、制御ソケットのスレッド、front のスレッド、stream と TLS の状態 | 今の `base` と同じ |
| M_fix | 核の固定の表。ポートの表、4 つ組の表、握手の途中、行の表は front に、枠の数で決まる配列は unit に分けます | 今の `fix` と同じ。分けても和は同じです |
| N_c × (f_s + f_r + r_f + h_f) | 接続の枠ごとの最初の予約と、記録の輪と区間の表 | 今の `floor_conn` と同じ |
| G | TCP の段を大きくする全体の予算 | [需要で育つバッファ](../../userspace/wgstack-buffers.md#予約と予算)の G。今の `boost` の項を置き換えます |
| M_udp_rx、M_udp_tx、M_frag、N_ping × c_ping | UDP の予算、再組み立て、ping | 今と同じ。すべて front です |
| M_ct | 受信の暗号文の置き場 | 今の `batch` の受信の部分と同じ |
| M_pt | 平文の置き場:今の 1 バッチの平文の領域と、unit ごとの block の上限の和 | 今の `batch` の復号の行き先を広げます |
| M_tx,front | front の送信の枠 | 今の `batch` の送信の部分と同じ |
| M_dev | WireGuard の device のキューとセッションの状態 | 今の `device` と同じ |
| M_relay | 中継の状態、大きいバッファ、応答のバッファ、handle の層の表 | 今の `tcp relay`、`tcp bulk`、`udp relay`、`tables`、`driver`。表の行は unit の枠の数に分け、和は同じです |
| M_unit,u | unit u の固定の値 (次の節) | 新しい項 |
| M_helper,h | helper h の固定の値 (次の節) | 新しい項 |
| M_ring | executor の間の捨てない輪 (次の節) | 新しい項 |

## unit と helper ごとの項

値は MTU を受け付ける最大の 9,216 byte で数えます。

| 項 | 中身 | 見込み (推定) |
|---|---|---|
| M_unit,u | 制御の輪 16 枠 × MTU | 約 0.15 MiB |
| | 受け口の輪 2,048 記述子 × 32 byte | 64 KiB |
| | chunk の置き場に残す分 32 個 × 16 KiB | 0.5 MiB |
| | 中継の大きいバッファの残す分 8 個 × 32 KiB | 0.25 MiB |
| | 平文の block の上限 16 block × 16 KiB (M_pt の中の分) | 0.25 MiB |
| | タイマーの輪、出力と知らせの list の先頭、数え | 小さい |
| M_helper,h | スレッドのスタック (測った最大の使用量の 2 倍以上、仮の値は 256 KiB) | 0.25 MiB |
| | 送信の枠 16 枠 × (MTU + 32 byte と header) × 2 | 約 0.3 MiB |
| | poller の知らせの列と貸し出しの輪 | 小さい |

受け口の輪の記述子の上限は、block の上限とは別に置きます。
16 KiB の block は最小の 40 byte の packet を約 400 個持てるので、block の上限だけで輪を抑えると、小さな packet で 6,500 個ほどの記述子が要るためです(計算)。
記述子が上限に達した時も、block の上限と同じく TCP の segment を捨てます。

helper のスレッドは tokio の実行環境を持たないので、実行環境の項は poller の知らせの列だけです。

## executor の間の輪

| 輪 | 容量 | 合計の見込み (推定) |
|---|---|---|
| 制御の輪 (front から unit) | 4 × N_c,u + 2。記述子は 64 byte 程度 | Σ で 4 × N_c × 64 byte。N_c = 2,560 で約 0.66 MiB |
| 返却の輪 (unit から front) | 2 × N_c,u。行の中身を運ぶので 96 byte 程度 | Σ で 2 × N_c × 96 byte。約 0.47 MiB |
| 戻しの輪 (unit から front) | unit ごとに 64 | 小さい |
| block の返却の輪 | 平文の block の数 | 小さい |
| 受け渡しの輪 | executor ごとに M | 小さい |

制御の輪と返却の輪の合計は、unit の数によらず N_c で決まります。

## 増える量の見込み

| n_cpu | H と M | 増分の見込み (推定) |
|---|---|---|
| 1 | 0 | 0 |
| 2 | 1 | 約 2.9 MiB |
| 4 | 3 | 約 6.5 MiB |
| 8 | 7 | 約 13.6 MiB |

内訳は、unit ごとに約 1.21 MiB、helper ごとに約 0.57 MiB、輪の合計の約 1.1 MiB です(推定)。
A+ は 8 vCPU で常駐のメモリを 8.4 MiB 増やしました (#808 から #810)。
U の増分の大半は、unit ごとに残す chunk と大きいバッファ、helper の送信の枠です。
残す数と送信の枠を減らすと、chunk の確保と解放と送り出しの system call が増えるので、値は P0 で CPU と比べて決めます。
見込みには、poller の保持と、核を作り直した後の型の大きさの未測定の分が残ります。
メモリの線は、P0 でこれらを測った後に決めます([所有者に決めてもらうこと](README.md#所有者に決めてもらうこと))。

## 全体の予算と unit の credit

TCP の段の予算 G、UDP の予算、chunk の予約は、全体で 1 つの数と、unit ごとの credit で数えます。

- 不変条件:全体の空き + Σ_u (unit u の credit の残り + unit u の保有者が借りた量) + front の分 = G
- 補充:unit の credit が下の線を下回ったら、その unit の実行の終わりに全体の空きから 1 単位 (仮の値は 1 MiB) を CAS で取ります
- 返却:credit が上の線を超えたら、超えた単位を全体に返します
- 保有者の借り:接続の段を大きくする時は、unit の credit から借ります。
  credit が足りず全体の空きも無い時は、今の段のまま続けます
- 回収:全体の空きが無い時は、求めた unit がほかの unit の回収の印を立てます。
  印を見た unit の持ち主は、次の実行で需要の無い保有者を最初の段に戻し、空いた分を全体に返します
- 需要で育つバッファの設計との違い:その設計は回収した借りを求めた接続へ直接渡します([需要で育つバッファ](../../userspace/wgstack-buffers.md#育つ条件))。
  U では unit をまたぐ直接の受け渡しを持たず、全体の空きに返すので、別の unit が先に取ることがあります(設計判断)

credit の残りは G の内側なので、二重に数えません。
段を変えるのは unit の持ち主の 1 回の実行の中なので、段を変える間の一時の保持を接続の予約の内に収める今の論証はそのまま成り立ちます。

## 固定の置き場と大きさの区分

| 区分 | 大きさ | 置き場 | 取る者と返す者 |
|---|---|---|---|
| chunk | 16 KiB | front と unit の状態の置き場と、予約の内の確保 | 状態の持ち主が取って返します |
| 平文の block | 仮の値は 16 KiB | 1 つの M_pt | front が取り、unit の持ち主が返します |
| 送信の枠 | MTU の最大 + 32 byte と header | executor ごと | 取った executor が返します |
| 受信の暗号文の枠 | 65,535 byte (GRO の 1 つ) | 1 つの M_ct | front が取り、復号の後に返します |
| 記述子と知らせ | 32 から 96 byte | 輪の配列 | 輪の中を動くだけで、確保しません |

### chunk と大きいバッファの置き場

接続は unit を移らないので、chunk と中継の大きいバッファは unit の状態の置き場に返り、どの executor が実行していても同じ置き場を使います。
front は今と同じく chunk を 64 個、大きいバッファを 16 個まで残し、unit はそれぞれ 32 個と 8 個まで残します(設計判断、値は P0 で決めます)。

### unit ごとの block の上限

平文の block は複数の unit の packet を含むことがあり、unit が押さえるメモリは参照を持つ block の数で決まります。

- 数え方:front は、復号した packet を作業の block に置いた後、その packet を unit に渡す時に、その block への unit の参照を初めて持つなら unit の数を 1 つ増やします。
  unit の持ち主が block の返却の輪で返した時に減らします
- 上限:unit ごとに 16 block を上限にします。
  上限に達した unit には、その packet を渡さずに捨てて数えます。
  復号は渡す先が分かる前に作業の block で行うので、捨てるのは参照を持たせないことです
- 作成の知らせ:握手の最後の ACK の参照も、その unit の数に入れます。
  上限に達した unit は接続を置く先から外します([unit の選び方](ownership.md#unit-の選び方))
- 置き場の大きさ:M_pt は、front の 1 バッチ分の作業の block と、M × 上限 以上にします。
  このため、遅い unit がいても front は常に空いた block を取れ、読みを止めません
- 変換の無い形:engine の置き場から枠を貸す link (TUN など) は、同じ数えに入れます。
  link が自分の枠を貸す link (AF_XDP の UMEM) は、スレッドをまたぐ前に block に写します(設計判断)

## 予算と枠を 1 つにする値

置き場の枠と予算は、`Lease` (仮の名前) という 1 つの型の値で表します。
`Lease` は複製できず、捨てると枠と予算を置き場に返し、executor の間で動かすと予算の数えも一緒に動きます。
上界の式の各項は置き場の容量で、`Lease` の行き先によりません。

## 所有者が挙げた領域と項の対応

| 領域 | 項 |
|---|---|
| TCP の状態 | M_fix の接続の枠、握手の途中の表、4 つ組の表 |
| TCP の送受信のバッファ | N_c × (f_s + f_r) と G |
| SACK、RACK、再送 | 再送のデータは送信の輪の chunk (f_s と G)、記録は r_f と G の段の配列、区間は h_f と G の段の配列、RACK と TLP の値は接続の枠の中 |
| TIME_WAIT と FIN_WAIT_2 | M_fix の行の表 |
| 再組み立て | M_frag |
| UDP | M_udp_rx、M_udp_tx、M_fix の endpoint の表 |
| WireGuard の暗号のバッファ | M_ct、M_pt、M_tx,front、M_helper,h の送信の枠、貸し出しの輪 |
| WireGuard の状態とキュー | M_dev |
| 制御の message | M_ring、M_fix と M_unit,u の制御の輪 |
| タイマー | M_fix のタイマーの節と、握手の途中と行の list |
| スレッドのスタック | M_base、M_helper,h のスタック、今と同じ名前の解決のスレッドの項 |
| 実行環境 | M_base と M_helper,h の poller |
| 中継 | M_relay と M_unit,u の大きいバッファ |
| 割り当て器 | 論理の上界の外。RSS の上界で数えます (次の節) |

二重の数えが無いことは、置き場の容量だけを項にすること、枠の数で決まる配列と表の和を全体の数と等しくすること、credit を G の内側の数にすることで示します。
数え漏れが無いことは、executor のスレッドの確保をすべて上の置き場から行い、置き場の外の確保を数えの試験で 0 と確かめることで示します([メモリの試験](verification.md#メモリの試験))。

## 論理の上界と RSS の上界

論理の上界は上の式の和です。
RSS の上界は、論理の上界に次の分を加えた値です。

- 割り当て器の丸めと管理の領域:起動の時の確保と流れごとの確保の大きさに、割り当て器ごとに測った係数を掛けます
- 割り当て器の arena:製品の build は musl で、割り当て器は 1 つの heap を持ちます。
  glibc の build はスレッドごとに arena を作るので、arena ごとの断片化の余裕を加えます。
  U では、unit の chunk と中継の状態を、別の executor が実行する時に解放することがあり、glibc では確保した arena と違うスレッドからの解放になります。
  その分の断片化は glibc の build で測ります (未確認)
- スタック:上界はスタックの全体で数えます
- ページの丸め:大きな置き場の端の切り上げです

ラボの確認は今と同じく、RSS が上界と決めた余裕の和以下であることを n_cpu ごとに確かめます([agent の上界の表](../../v2/agent-bound.md))。

## カーネルの保持

今の上界は、カーネルのソケットのバッファを数えません([agent の上界の表](../../v2/agent-bound.md)の起動の行の説明)。
U でも数えず、executor ごとの poller (Linux の epoll) のカーネルの保持も同じ扱いです。

## 尽きた時の規則

どの資源も、尽きた時に新しい保持を拒み、既存の保持を追い出しません([尽きたときの動作](../../userspace/wgstack.md#尽きたときの動作))。

### TCP の尽きた時

| 資源 | 扱い |
|---|---|
| 接続の枠 | 空きのある unit に置きます。どの unit も外れた時は、最後の ACK を捨てて握手の途中の行を残します |
| 握手の途中の表 | cookie を返します。今と同じです |
| 段の予算 | 今の段のまま続け、回収を求めます |
| 送信のバッファと記録 | アプリケーションの書き込みに `WouldBlock` を返します。再送のデータは捨てません (I4) |
| unit の block と記述子の上限 | その unit の TCP の segment を捨てて数えます。経路での損失と同じ扱いです |
| 平文の置き場 | 上限の和より大きく取るので、unit のために尽きることはありません |
| 送信の枠と貸し出し | unit の持ち主が核から引くのを止めます。データは核の送信の輪に残るので失いません |
| 制御の輪と返却の輪 | 容量を知らせの数の上界から決めるので、満ちません |
| 戻しの輪 | SYN を捨てて数えます。相手が SYN を送り直します |

unit の上限で捨てる segment は、まだ確認していない受信のデータなので、I4 の「再送に要る未確認のデータを黙って捨てない」には当たりません。

### UDP の尽きた時

| 資源 | 扱い |
|---|---|
| 受信の予算 | datagram を捨て、ICMP を返しません。今と同じです |
| 送信の予算 | 送信は `WouldBlock` を返し、応答の送信 (`send_to_latest`) は古いものから捨てます。今と同じです |
| 会計の不整合 | engine の UDP を止めます。TCP は止めません |

### 回復

入力が止まると、平文の block、送信の枠、輪の記述子は unit の処理の後にすべて置き場に戻ります。
段の予算は、需要の無い保有者を最初の段に戻す今の回収の規則で戻ります。
入力が止まった後に保持が戻ることを、n_cpu が 2 以上の敵対的な保持の試験で確かめます([メモリの試験](verification.md#メモリの試験))。
