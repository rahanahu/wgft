# JSON の符号化と Go に由来する細部

agent と server の間の JSON と `agent.json` は、Go の `encoding/json` が書いて読みます。
正しい相手どうしでは、どの JSON の実装でも同じ値になります。
壊れた入力と境界の値では、Go の `encoding/json` の性質が振る舞いを決めます。
この文書はその性質と、Go 以外の実装が受けなければならない形と拒んでよい形を定めます。
`wire` は stream のメッセージと登録の要求と応答を指し、`agent.json` は[認証情報](credentials.md)を指します。

Go の性質として書く挙動は、Go 1.27.2 の `encoding/json` (v2 の上に実装した v1 の API) のものです。
Go を上げて挙動が変われば、`proto` の `TestSpecWireQuirks` が fixture との違いとして検出します。

## 書く側の規則

- キー:小文字の正規のキーだけを書き、同じキーを 2 回書きません。
  Go 以外の実装が書いた `agent.json` を v1 に戻して読めるようにするためです
- フィールドの順:構造体の宣言の順で書きます。
  各メッセージの順は [messages.md](messages.md) と fixture のとおりです。
  JSON の意味はキーの順に依りませんが、Go の v1 はこの順で書き、golden の試験はこの順で比べます
- 省略:`omitempty` の付いたフィールドは、値が零の値のときに書きません。
  零の値は、文字列の `""`、数の `0`、真偽の `false`、ポインタと配列の不在、長さ 0 の配列です。
  各フィールドの省略の有無は、各文書の表に書きます
- 配列の `null`:Go の nil の配列は `null` になり、長さ 0 の配列は `[]` になります。
  v1 の server は全体状態の `rules` を常に `[]` 以上で書き、agent はハートビートの `rules` を常に `[]` 以上で書きます
- 整数:10 進の整数で書き、指数と小数点を使いません
- 不正な UTF-8:文字列の中の不正な UTF-8 の byte は、1 byte ごとに U+FFFD に置き換えて書きます
- 制御文字:`\b`、`\f`、`\n`、`\r`、`\t` は短い escape で書き、残りの U+0000 から U+001F は `\u00XX` の形で書きます。
  U+007F はそのまま書きます

### Go の性質:HTML のための書き換え

`json.Marshal` は `<`、`>`、`&` を `\u003c`、`\u003e`、`\u0026` に書き換えます。
U+2028 と U+2029 は、書き換えを止めた `json.Encoder` でも `\u2028`、`\u2029` に書き換えます。
16 進の数字は小文字です。

v1 の書き手ごとの扱いは次のとおりです。

- agent の stream のメッセージ:書き換えを止めて書きます (`SetEscapeHTML(false)`)。
  U+2028 と U+2029 だけは書き換えます
- server の stream のメッセージと登録の応答:書き換えて書きます
- `agent.json`:書き換えて書きます (`json.MarshalIndent`)

どちらの形も同じ JSON の文字列を表すので、読む側の結果は変わりません。
Go 以外の実装は、どちらの形も受けなければなりません。
書く側は、読む側の上限に関わるときだけ形を合わせます。
agent のハートビートは書き換えを止めた形で、理由の長さの上限を見積もっています ([messages.md](messages.md#heartbeat))。

## 読む側の規則

Go の v1 の読み手は `json.Unmarshal` で構造体に読みます。
Go 以外の実装に求める読み方は 2 段に分かれます。

### 受けなければならない形

Go の v1 の書き手が書く形は、すべて受けなければなりません。

- キー:小文字の正規のキーです
- 知らないキー:読み飛ばします。
  誤りにはしません。
  新しい版の相手が加えるフィールドを読み飛ばすためです
- 省略したフィールド:`omitempty` で省いたフィールドは零の値として読みます
- 文字列:HTML のための書き換えをした形と、していない形の両方です。
  `\u2028` と `\u2029` の escape も含みます
- `null`:Go の書き手が `null` を書くフィールドです。
  例えば `agent.json` の `last_state` と、nil の配列です
- 時刻:零の値 `0001-01-01T00:00:00Z` を「値が無い」と読みます。
  `Z` と `+09:00` の形の時差と、最大 9 桁の秒の小数部を受けます
- 世代:0 から 2^64-1 の符号の無い 64 bit の整数です
- 整数:小数点と指数の無い 10 進の整数です
- 値の後ろの空白:`json.Encoder` は値の後ろに改行を書くので、受けます

### 拒んでよい形

Go の書き手が書かない形は、メッセージごと拒んで構いません。
拒むときは、その面で Go の v1 が読みの誤りに取る経路と同じ経路を取ります。
agent は読めない `state` をログに出して捨て、server は読めない最初のメッセージで 1008 で閉じ、2 通目以降は接続を捨てます ([stream.md](stream.md#接続の手順))。
受ける場合に Go の v1 と同じ値に読むための Go の性質は次のとおりです。

- キーの大文字と小文字:Go はキーを大文字と小文字を区別せずに照合します。
  照合は Unicode の単純な case folding によります。
  例えば `ſtate` (U+017F) も `state` に入ります
- 重複したキー:Go では後に出た値が勝ちます。
  大文字と小文字だけが違うキーも同じキーとして扱います。
  値がオブジェクトで、フィールドが構造体か構造体へのポインタなら、後の値は前の値に重ねて読みます。
  値が配列なら、後の配列が前の配列を置き換えます。
  Go 以外の実装が重複を受けるなら、後の値を採ります
- 不正な UTF-8:Go は文字列の中の不正な UTF-8 の byte を、1 byte ごとに U+FFFD に置き換えて読みます。
  対になっていない surrogate の escape (`\ud800`) も U+FFFD に読みます
- スカラーの `null`:Go は文字列、数、真偽、時刻、`PortRange` のフィールドの `null` で何も変えず、零の値のまま残します
- 9 桁を超える秒の小数部:Go は受けて、9 桁より後ろを捨てます
- 正規でない base64 と `listen_port`:[数と識別子の書き方](#数と識別子の書き方)と [messages.md](messages.md#go-の性質listen_port-の読み方) のとおりです

Go が誤りにする形は次のとおりです。

- 型の違い:文字列のフィールドに数が来るような型の違いです
- 整数の形:小数点か指数を含む数 (`1.0`、`1e0`) と、範囲の外の値 (`uint64` の負の数、`int` の桁あふれ) です
- 時刻の形:小文字の `t` と `z`、4 桁でない年です
- 全体の形:先頭の BOM、最上位がオブジェクトでない値、値の後ろの空白以外の文字です。
  ただし server の登録の API は `json.Decoder.Decode` で本文を読むので、最初の値の後ろの文字を見ません。
  Rust の server を作るときは、この違いを写すかどうかを決めます

Rust の `serde_json` の既定は、キーの大文字と小文字を区別し、構造体の重複したキーを誤りにします。
この既定は「拒んでよい形」の範囲に入るので、そのまま使えます。
fixture の `testdata/spec/wire/quirks.json` は、各例を Go の v1 が読んだ結果と、Go 以外の実装の扱い (`rust` が `must-accept` か `may-reject`) を持ちます。

## 時刻

時刻のフィールド (`time.Time`) は RFC 3339 の文字列です。

- 書く形:秒の小数部は末尾の 0 を除いて最大 9 桁で書き、0 なら書きません。
  時差は UTC なら `Z`、それ以外は `+09:00` の形です。
  v1 の書き手は、ハートビートの `last_handshake` を WireGuard の device が返した時刻のまま書くので、時差は agent のホストの設定で決まります
- 零の値:Go の零の値の時刻は `0001-01-01T00:00:00Z` です。
  `omitempty` は構造体の型に効かないので、`omitempty` の付いた時刻のフィールドも零の値を書きます。
  読む側は `0001-01-01T00:00:00Z` を「値が無い」と読みます
- 読む形:Go は `T` と `Z` を大文字だけ受け、年を 4 桁だけ受けます。
  秒の小数部は 9 桁を超えても受け、9 桁より後ろを捨てます。
  9 桁を超える小数部は Go の書き手が書かないので、Go 以外の実装は拒んで構いません
- 範囲:年が 0 から 9999 の外の時刻は書けず、書き手の誤りになります

## 数と識別子の書き方

- 世代:`generation` は 0 から 2^64-1 の整数です。
  JavaScript の倍精度の数で読むと 2^53 を超える値で精度を失います
- 版の番号:`protocol_min`、`protocol_max`、`server_protocol_version` は符号付きの整数として読みます。
  0 と負の値も読めて、意味の検査で拒みます ([stream.md](stream.md#版の交渉))
- WireGuard の鍵:base64 の標準の alphabet と `=` の padding で 44 文字にした 32 byte です。
  Go の v1 は `encoding/base64.StdEncoding` で読みます。
  Go の性質として、末尾の使わない bit が 0 でない表記を受け、文字列の中の `\r` と `\n` を読み飛ばします。
  Go の書き手はこの 2 つの形を書かないので、Go 以外の実装は拒んで構いません。
  書くときは正規の 44 文字だけを書きます
- ルールの ID:Web UI が付ける ID は ULID (26 文字の Crockford base32) で、`wgft rule add` が付ける ID は `r_` を前に付けた ULID です。
  利用者が書いた ID も受けるので、agent は ID を不透明な文字列として扱います。
  上限は 128 byte です ([ルールのスキーマ](../control/rules.md#53-ルールのスキーマ))
